# NBS2schematic

将 Minecraft NBS 音乐文件（Note Block Studio 格式）转换为「红石音乐」布局的 **.litematic 投影 schematic**（Litematica 投影 mod），摆好后手动铺设总线与开关、接通各链头即可播放。

## 使用方法

1. 双击打开 `index.html`（现代浏览器：Chrome/Edge 80+、Firefox 113+、Safari 16.4+，完全离线）。页面为**左右分栏**：左侧独立侧边栏 = 音轨池（列表随侧栏高度内部滚动，宽 680px = 340 的 2 倍；侧栏顶栏 ◀ **收起**后侧栏整体隐藏、右侧顶部出现「▶ 展开音轨池」按钮，状态跨歌保留），右侧 = 歌曲信息 / 速度分析 / 车道池 / 节奏型参考车道池 / 设置 / 布局编辑器 / 生成等全部组件（鼠标滚轮滚动）
2. 拖入 `.nbs` 文件（或点击选择）
3. 勾选要转换的声部（默认全选有声部的层，在左侧音轨池）
   - 可选：勾选某声部的**「节奏参考」**复选框 → 该声道每个音符在轨道 0 触发一次粒子特效（见下文「节奏参考声道」），**同时以勾选式并入右侧「节奏型参考车道池」**（默认并入第一条无冲突参考车道、放不下自动新建；也可直接把音轨**拖入**参考车道卡片指定车道）。**勾选只进参考车道池，不再自动在音轨车道池复制一份**；参考声道的行内只保留**「发声」**复选框（默认关 = **在普通轨道也发声**的显式开关：取消 = 普通轨道无盒、零声音（参考车道是纯虚拟参考，不生成任何结构，只剩节奏/音高粒子参考）；勾选 = 把音轨显式并入音轨车道池，普通轨道放真实盒发声；「节奏参考」与「发声」两选项位置固定相邻，勾选前后不移动）；**类型选型（绑定型 / 独立型）在参考车道池中按车道选择**——一条参考车道的全部成员声道共用同一类型，切换类型时成员「发声」状态保持原值（可自由开关；参考车道为纯虚拟参考，粒子恒产生，见下文）
4. 配置车道：把音轨池中的音轨**拖入**车道卡片即分配（音轨数量不限、同一音轨可重复拖入 = 占多个音符盒位齐响更响；点击标签 ✕ 移除；⧉ 复制 = 生成第二条相同链齐响加倍）。每张卡片顶部显示**冲突分析**（合并后同 tick 超 3 位的丢弃数），下方「简并建议」从**名称重复、音符少、乐器类型**三个角度给合并建议 + 无冲突打包方案（一键应用）；面板顶部自动检查**未分配音轨**并给出警告（可一键自动并入）。**节奏型参考车道池**（独立分区）：成员来自音轨池「节奏参考」勾选（勾选式并入）**或直接把音轨拖入卡片**（拖入即登记为节奏参考并入该车道，允许重复拖入占多个盒位齐响），卡片支持 **＋ 新增 / ⧉ 复制 / ✕ 删除 / 标签 ✕ 移除**，同样带冲突徽章，**头部带类型下拉（独立型/绑定型，作用于该车道全部成员）**；**参考车道是纯虚拟参考（2026-09-07 起不生成任何物理结构）**——只保留假定的 (dz, dy) 起点 + 3 盒位 Z 槽位作粒子锚点几何，可与普通车道任意并排（不参与碰撞校验）；**未勾选「发声」的参考成员标签标琥珀（「（静音）」）+ 分区级 ⚠ 提示**（普通轨道无盒，仅节奏/音高参考；想同时发声请在左侧音轨池勾选其「发声」）；把参考音轨**显式拖入音轨车道卡片**（或勾选其行内「发声」）即让普通轨道放真实盒发声
5. 在布局编辑器（Y-Z 截面）拖拽各链起点位置（含恒生成的**轨道 0**，琥珀色虚线「0」标记；音轨车道编号 1..n；**参考车道紫色点划线「R1..」标记**；**起点支持负 Y/Z**，网格生成时整体平移保证产物坐标非负；**Z=0 / Y=0 坐标轴加粗显示**），或用预置模板——**「单行 / 网格 / 放射」三模板均以 0 号车道（轨道 0）起点为中心对称排布，只重排音轨车道（参考车道为纯虚拟参考、位置不受预置影响，在右侧独立窗口拖动）**：单行 = Z 向两侧交替 ±3、±6…（偶数位 +Z 侧）；网格 = 中间行两侧 ±3 起逐行外扩、Y 向上下交替抬升（行距 = 设置区「网格/放射行距」，默认 5）；放射 = 按到中心欧氏距离由近及远取位（Z 步长 3、Y 步长 = 行距，同距 +Z 侧优先）
6. 查看「播放速度分析」：主链 1 档中继器、游戏内 `/tick rate` 校正命令、跟随播放指引；设置：自定义乐器映射、**独立型参考音高步长 sfxPitchStep**（0–8，默认 1）、**目标 Litematica 版本**（1.19.4 ~ 1.21.11 十档可选，默认 1.21.11，见下文「多版本兼容」）
7. 点击「生成 schematic」→ 自动**产物自检**（解码刚生成的 NBT 与内存网格逐格比对 + gzip 往返校验，失败不亮下载按钮）→ 检查统计与三视图预览 → 下载 `.litematic`（导入新 NBS 会自动清除旧结果与预览）；**有参考声道时**生成后额外出现「⬇ 下载粒子数据包 (.zip)」按钮——完整数据包 zip（pack.mcmeta + data/nbs2sfx/…/<tick>.mcfunction），与 .litematic 配套
8. 放入 `.minecraft/schematics/`，在对应 MC 版本（与所选「目标 Litematica 版本」一致）中用 Litematica 加载投影；**有参考声道时**把粒子数据包 zip 解压到 `.minecraft/datapacks/`（游戏内 `/reload`，或开图前放入）
9. 手动铺设总线与开关接通各链头（触发区由用户自铺，见下文「触发区（用户手动放置）」）；播放前按面板提示执行 `/tick rate <R>`（若 R≈20 可跳过），触发播放并跟随链移动

## 电路设计

- **主链**：每 NBS tick 占 2 格 X——中继器格（**恒 1 档**，周期 2 游戏刻，零抖动）+ 音符格。**中继器朝向语义**：`facing` 是**输入侧**（官方 wiki：「from the output side to the input side」，与放置时面向相反），输出朝对面 → 信号流向 +X 的中继器写 `facing=west`（触发区已移出产物，图中所有中继器都在主链，恒 `facing=west`；曾误按「输出方向」写导致整条链断链，validate/smoke 均有逐格朝向断言回归保护）
- **速度模型（NBS 是基准，游戏去适应它）**：主链 1 档中继器周期恒 2 游戏刻/NBS tick（用户游戏内实测校准：音符盒/红石粉 0 延迟）；播放时游戏内执行 `/tick rate R = 2 × tempo` 精确校正（tempo=10 时 R=20 即默认 20tps 无需调整；tempo=5 时 R=10、tempo=8.5 时 R=17）
- **音符格（音符盒导电结构）**：主音符盒放在中继器输出端正前方（被强充能 → 发声 + 导电 + **激活两侧紧挨的第 2/3 音符盒**，三个同刻齐响）；无音符时该位置放红石粉直通传导。音符盒是红石导体（minecraft.wiki 查证），信号不中断
- **底座**：音符盒下方为对应音色方块（harp→雪块、bit→绿宝石块）；雪块主体框架只保留最中心的线，中继器格中心底座恒为雪块（蜂蜜块小节标记已取消——蜂蜜块非满方块，碰撞箱仅 14×14×15，不适合垫中继器）。**防掉落托底**：snare 音色底为沙子（重力方块，会掉落），生成时其正下方自动补一个雪块托住（用户游戏内实测发现）
- **触发区（用户手动放置）**：总线 / 各链下降 tap / 启动开关（按钮/拉杆/压力板）已按用户要求**从产物中整体移除**（用户确认：手动放置）。产物只含各轨道主体（主链中继器 + 音符盒 + 底座 + 轨道 0 顶层导轨）；**每条链的链头是 X=0 处的 1 档中继器，其输入端（-X 侧）留空**，用户自铺总线（如 Z 向红石粉 + 下降/水平线）从任意高度接通各链头输入端，开关自便（拉杆/按钮/压力板等）。历史设计（纯红石粉 Z 向总线 + 插座候选搜索 + 自然延迟 |zc−zStub|+k+1、多车道首音先后响起）仍可直接照搬实现，不再内置
- **音高**：NBS `song_key` → note_block `note` 线性绝对音高 `note = key − 33`（key 33=F#3→note 0、45=F#4→note 12、57=F#5→note 24，有效区间恰好覆盖音符盒 0-24 全音域；NBS Studio 官方红石导出即此公式与 33-57 范围）；key 越界的音（常见于微音移调）跳过并计数，主位以红石粉代位保通路
- **车道**：音轨池（NBS 声部）**拖拽**分配给车道池中的任意车道（多对多）；**音轨数量不限**，卡片顶部实时显示冲突分析（同 tick 超 3 个音符盒位时丢弃并计数）；同一音轨可在同一车道重复出现（占多个音符盒位，同 tick 齐响 = 双倍音量）；**⧉ 复制**车道 = 第二条独立链播放相同音轨（齐响加倍）；每条车道 = 一条中继器链 + 主/第2/第3 三个音符盒位
- **页面布局**：左右分栏——左侧独立侧边栏放**音轨池**（勾选/参考/发声 + 拖拽源，列表随侧栏高度内部滚动），**可折叠**（侧栏顶栏 ◀ 收起 = 侧栏**整体隐藏**，右侧顶部出现「▶ 展开音轨池」按钮恢复，**sticky 钉在右侧滚动区顶部、不随滚轮划走**；展开 = 680px（340px 的 2 倍）；折叠状态存全局 UI 键 `nbs2schematic:ui`，跨歌保留）；右侧为歌曲信息 / 速度分析 / 车道池 / **节奏型参考车道池** / 设置 / 布局编辑器 / 生成等全部组件（滚轮滚动）；窄屏（≤900px）退化为上下堆叠 + 整页滚动（折叠 = 隐藏音轨池区）
- **参考车道池（节奏型参考车道池，纯虚拟参考）**：独立网页分区，类车道池卡片（＋ 新增 / ⧉ 复制 / ✕ 删除 / 成员标签 ✕ / 冲突徽章 / **类型下拉**），成员两种进入方式：①音轨池「节奏参考」**勾选式**并入（默认第一条无冲突参考车道、放不下自动新建，与音轨车道勾选语义一致；「全选/全不选」时整体重建，每 3 条参考成员一车道，新建车道默认独立型）；②**拖拽式**——左侧音轨池的音轨直接拖入卡片投放区（拖入即登记为节奏参考声道并入该车道；允许重复拖入同一车道 = 占多个粒子槽位齐响；同一音轨已在其他参考车道时移入目标车道）。每条参考车道 = 一个**虚拟的假定车道**（起点 + 3 盒位 Z 槽位：tracks 顺序 → 槽 0/1/2 → Z +0/+1/−1），**2026-09-07 起不生成任何物理结构**（无中继器/雪块/音符盒/命令方块），只作绑定型粒子的锚点几何；**网格尺寸只由真实链（轨道 0 + 音轨车道）决定**，参考车道虚拟起点即使超出网格范围也不扩格；**与普通车道可任意并排**（不参与碰撞校验）。**类型选型按参考车道**（存 `lane.type`，构建侧按成员所在参考车道取类型）：一条车道的全部成员声道共用同一类型——成员 refLayers 类型跟随车道、sound 保持原值（切绑定型**不再强制发声**）；同一成员分属多条车道时按「绑定优先」合并。复制车道连同类型一起复制。**「发声」= 普通轨道是否放真实盒**：未勾选的参考成员标签标琥珀（「（静音）」）、分区级 ⚠ 提示、拖入时生成状态行提示；**粒子恒产生，不受「发声」影响**（参考意义）。参考车道默认起点在音轨车道右侧（`dz = i×3 + 6`，避开音轨车道 `i×3+3` 与轨道 0 的 Z=0；预置模板只重排音轨车道，见上）
- **默认轨道 0**：恒生成于车道池顶部（固定卡片「轨道 0（默认）」，不可删除、不分配音轨）。物理上是一条**真实的无音符中继器链**（与普通无音符车道结构完全相同：中继器链 + 雪块底座，链头同样留空待手动接总线，无音符），唯一特征是**顶层导轨**：在 y = 起点 Y + 2 处沿 +X 铺 1 高 × 1 宽雪块轨（与主链同长，x=0..xMax−1，只写空气格不覆盖其他结构），每 32 格替换 1 格为 `minecraft:ochre_froglight`（赭黄蛙灯，ID 经 Mojang 官方 1.21.11 server.jar 查证），即 X=32, 64, 96…（链头 X=0 保持雪块）。蛙灯与雪块同为不透明满方块、无红石功能，纯装饰标识。**节奏参考声道的粒子命令方块统一放在轨道 0**（该 tick 段主位底座，见下文「节奏参考声道」），是整张图的粒子触发链。起点在布局编辑器中可拖拽（默认 Z=0，**可拖到负 Y/Z**）；为轨道 0 让出 Z=0，音轨车道 1..n 的默认起点整体右移 +3（`dz = i×3 + 3`，i 从 1 起）；**空车道池也可生成**（产物 = 仅轨道 0 链，总线/开关由用户手动放置）
- **负起点支持**：任意链（含轨道 0）起点允许负 Y/Z。产物网格整体平移保证非负——`yOffset = −min(0, 各链 yb)`、`zOffset = 1 − min(0, 各链 zc)`（**只在最小值确为负时平移**，全非负起点时退化为旧值 yOffset=0/zOffset=1，产物与旧版一致）；第 3 音符盒占 zc−1 与负起点共同决定 zOffset；绑定型粒子偏移是两链坐标差，平移对其无影响；snare 沙子托底按网格 y≥1 扫描补雪块，平移后凡底座行下方有空间（非最低链）照常托底（最低链底座在网格 y=0、下方无空间，与既有全非负行为一致）
- **未分配检查**：池中未被任何车道引用的音轨不会出现在 schematic 中，面板顶部自动警告并列出编号，「＋ 自动并入」逐条尝试无冲突并入现有车道（放不下则新建车道）
- **布局编辑器（双窗口，2026-09-07 参考车道虚拟化后）**：Y-Z 截面画布 ×2（滚轮缩放、拖拽平移、点击选中、方向键微调，Shift = 5 格大步）——**主窗口**管轨道 0（琥珀虚线「0」，不可拖）+ 音轨车道（实线，按主导乐器色），参考车道以**半透明虚线背景**显示、不可拖；**参考车道独立窗口**（参考车道紫点划线「R1..」，可拖；普通车道 + 轨道 0 灰点背景不可拖）。两窗各自独立缩放/平移；**Z=0 竖轴 / Y=0 横轴加粗提亮**（2px、#4a5568），轴标签 Z → / Y ↑ 加大加粗，便于定位。起点重叠 = 错误（阻断生成，**只校验各窗口内可拖的链之间**——参考车道与普通车道同位不报错）、间距 <3 格 = 警告（串扰提示）。「缩放到全部」自适应视图
- **简并建议**：从名称重复（含相似名，如 Main/Main2 归一归组）、音符少（≤10 可并入其他车道）、乐器类型（主导乐器相同）三个角度给出合并建议；「无冲突打包」贪心算法**名称重复优先**（同名归一组整体前置、组内音符少先；放置时优先聚入已含同名成员的车道，容量允许下同名成员绝不拆散到多余车道），随后常规简并（常见乐器先 → 音符少先；加入车道需所有 tick ≤3 位）给出最少车道方案，可一键应用
- **播放速度**：`/tick rate` 为 vanilla 命令（Mojang 官方 1.20.3 更新日志查证，1.21.11 可用，需管理员权限，范围 (1, 10000)，改回 `/tick rate 20` 恢复；fabric-carpet 1.4.123+ 已移除自有 /tick）

## 跟随播放（音符盒可听范围约 48 格，链会沿 +X 推进）

链推进速度 = 2 × tempo 块/秒（每 tick 恒 2 格，面板会显示本曲数值）。产物为**各轨道主体**（不含触发区——总线/开关由用户手动放置；不含跟随装置——骑猪跟随装置已按用户要求移除）：

- **tempo ≤ 5**（速度 ≤ 10 块/秒）：创造飞行跟随（约 10.9 块/秒）——F3 将 facing 对齐 0° 后按住 W 直飞
- **更快**：游戏内自建骑乘 + 命令方块 tp——召唤并骑乘带 tag 的猪，循环命令方块每游戏 tick 前移 2/D 格：`/execute as @e[tag=rmr,type=pig] at @s run tp @s ^0.5 ^ ^`（步长按面板提示），与链精确同步
- 建议拉大模拟距离或 `/forceload add` 常加载链所在区块（跟随到位时前方区块已加载，信号不会断）

- **版本头统一写 `Version=6 / SubVersion=1`（最大兼容值）**：Litematica 读取器对 `Version` 做区间检查 `[1, SCHEMATIC_VERSION]` 且不检查 `SubVersion`（10 个分支 `LitematicaSchematic.readFromData` 源码确认）；≤1.20.4 分支 `SCHEMATIC_VERSION=6`、≥1.21 分支 `=7`，故写 6 全分支可打开（写 7 会被 ≤1.20.4 拒绝）。
- **方块状态跨版本零转换**：所用方块（雪块/橡木板/石/玻璃/黏土/金块/硬冰/骨块/铁块/灵魂沙/南瓜/绿宝石块/干草块/萤石/红石粉/中继器/音符盒）全是 1.13 扁平化后命名从未变化的古老方块，各版本 Litematica 的 DataFixer 路径不会改动它们；赭黄蛙灯（轨道 0 顶层导轨）1.19 新增，支持的目标版本全部 ≥1.19.4，命名同样跨版本一致。
- DataVersion 数值取自 Mojang 官方 server.jar 内嵌 version.json（2026-08 查证）；SCHEMATIC_VERSION 分支矩阵取自 sakura-ryoko/litematica（官方 maruohon/litematica 的 fork）各 LTS 分支源码。

## 节奏参考声道（粒子特效）

**特效分类（3 类框架，参考车道池底部「粒子特效总览」展示当前种类与效果描述）**：

| 类别 | 参数来源 | 状态 |
|---|---|---|
| **① 触发型** | 由音符触发，参数由 **1 个音符**决定 | 已实现（见下；当前条目：end_rod 螺旋展开） |
| **② 连接型** | 特殊的触发型：连接**前后两个音符**，参数由 2 个音符决定（如起点 = 前一音符盒位、终点/形态 = 当前音符盒位与音高） | 规划占位，暂未实现 |
| **③ 背景型** | 与具体音符无关，按**乐曲小节间隔**周期性激活（铺底氛围） | 规划占位，暂未实现 |

把某些声部标记为**节奏参考**：该声道的每个音符在轨道 0 触发一次粒子特效。**粒子恒产生，不受「发声」勾选影响**（「发声」只决定普通轨道是否放真实盒）。参考分**两种类型**（**选型在参考车道池中按车道选择**，该车道全部成员共用；同一首歌不同车道可混用）：

| 类型 | 发声 | 粒子中心 | 粒子偏移（CB 相对坐标，构建时求解） |
|---|---|---|---|
| **绑定型** | 可开关（「发声」= 普通轨道放真实盒；未勾选时普通轨道零盒零声音，只剩参考粒子） | **参考车道的虚拟盒位**（参考车道纯虚拟不生成结构，盒位 = 车道起点 + 槽位 Z +0/+1/−1 对应 tracks 顺序；音轨车道的重叠盒不触发粒子），每 tick 触发一次 | `offset = 参考车道虚拟盒位 − 轨道 0 CB 坐标` = `(0, (yb_参考车道+1) − yb_轨道0, (zc_参考车道+槽位) − zc_轨道0)`，槽位：主位 0 / 第2位 +1 / 第3位 −1 |
| **独立型** | 可开关（同上） | **轨道 0 链上、与 CB 同高**（垂直偏移恒 0） | `(0, 0, (clamp(note,0,24) − 12) × sfxPitchStep)`，note = key − 33（音高 12 居中） |

- **所有偏移都按轨道设定实时计算**（车道起点 dz/dy、槽位、目标音高），不取手工常数；同一 tick 的多个粒子行各带各自的计算偏移
- **sfxPitchStep**：独立型音高 → Z 偏移步长（格/半音），设置区可调 0–8（默认 1）；音高 12 偏移为 0，更高音向 +Z、更低音向 −Z

**触发机制（统一轨道 0）**：对每个有参考音符的 tick t（绑定型 ∪ 独立型任意），在**轨道 0**该 tick 段主位（段首 X+1，恒 1 档时即 X=2t+1）**底座层**（y = 轨道 0 起点 Y）把雪块替换为 `minecraft:command_block[facing=up]`，其 `Command = function nbs2sfx:<t>`（t 为 0 基 NBS tick）。轨道 0 是无音符链，主位信号层恒为红石粉——红石粉置于机制正上方会激活下方方块（wiki Redstone power），信号到达该格的 tick 即音符盒发声的同 tick，粒子与演奏严格同步。每 tick 至多一个命令方块；`<t>.mcfunction` 含该 tick **全部参考音符**的行（绑定行在前按车道放置顺序、独立行在后按声部升序，每音符一行）。
- 绑定型声道**未分配任何参考车道**（未勾选参考/被移出）时无虚拟锚点 → 其粒子整体跳过并警告（丢弃明细留「未分配参考车道」记录）；若该 tick 因此无任何粒子行，命令方块回退还原为雪块（不产出指向空 function 的方块）

**粒子数据包**：生成时有参考声道即打包完整数据包 zip（STORE 压缩、零依赖自写 zip 写入器 + CRC32）：

```
pack.mcmeta                        # ≤1.21.8 写 pack_format 整数；≥1.21.9 写 min_format/max_format
data/nbs2sfx/function/<t>.mcfunction   # 1.21 起目录名 function（1.21/24w21a 起 functions→function 改名）
```

- 粒子命令基础文本固定（用户提供的 `particleex polarparameter …` 模组命令，逐字写死不做修正），**仅坐标段 `~ ~2 ~` 被替换为计算偏移 `~dx ~dy ~dz`**，命令其余部分（粒子/颜色/速度/表达式/寿命）保持原样
- 命名空间固定 `nbs2sfx`；mcfunction 文件名 = tick 编号
- **使用**：zip 内容解压到 `.minecraft/datapacks/`（游戏内 `/reload` 或开图前放入），依赖用户自有的 `particleex` 模组命令；与 .litematic 版本头一致的目标版本对应正确的 pack format 与目录名（1.19.4~1.20.x 用 `functions/`，1.21+ 用 `function/`）
- pack format 数值经 Mojang 官方 jar 字节码查证：1.19.4=13 / 1.20.1=15 / 1.20.4=26 / 1.21=48 / 1.21.3=57 / 1.21.4=61 / 1.21.5=71 / 1.21.8=81 / 1.21.10=88 / 1.21.11=94.1；25w31a 起 `pack_format` 被 `min_format`/`max_format` 取代（1.21.11 jar 确认旧字段仅触发 deprecated 警告仍被解析，故新写法按目标版本自动选择）

## 状态持久化

- 车道分组、起点位置（含轨道 0）、**参考车道池（refLanes，含每车道类型 `type`；旧存档无此字段 → 空池）**、音轨勾选、**参考声道状态（refLayers，值为 `{type:'bound'|'independent', sound}` 对象；恢复时成员类型跟随其所在参考车道）**、设置（目标版本 / 自定义乐器映射 / **sfxPitchStep**）自动保存到 `localStorage`，key 为 `nbs2schematic:v1:<FNV-1a 哈希(文件名:大小)>`——同名不同内容的 NBS 不会误恢复
- 变更点（勾选/参考/类型/发声/拖拽/复制/删除车道、预置布局、设置修改）防抖 300ms 落盘；重新打开同一首 NBS 时自动恢复并在状态行提示「已恢复上次编辑状态（时间）」；旧存档无 refLayers 字段时按无参考处理，**旧 bool 值（true/false）自动迁移为独立型**
- 存储不可用（隐私模式/无头环境）时静默降级，不影响主流程
- **自动重建会重置起点语义**：「全选 / 全不选 / 自动分配 / 应用打包建议 / 加载新 NBS」触发整体重建，起点按车道下标 `dz = i×3 + 3`（音轨车道）/ `dz = i×3 + 6`（参考车道）重排（为轨道 0 让出 Z=0；轨道 0 自身起点不受影响）；单个音轨的勾选/取消勾选走**增量增删**（保留现有车道分组与起点，勾选时优先并入第一条无冲突车道、否则新建，取消勾选后空车道保留、可再拖入音轨复用；参考勾选同理，勾选式并入参考车道池）

## 错误诊断

- NBS 解析失败时报**字节偏移**（`文件意外结束 ｜ 字节偏移 N/总长 M`）与**已解析部分**统计（层数/音符数/自定义乐器数），便于定位损坏位置
- **格式嗅探 + 规模上限**：NBS 是无魔数裸二进制，解析前做头部启发式校验——版本号仅接受 v0（旧格式）/v4/v5/v6，声部数 ≤4096、音符数 ≤200 万、文件 ≤256MB（loadFile 前置拒绝）；选错文件（.txt/随机二进制）会提前报「不是有效的 NBS 文件」并提示确认文件类型，而非硬解到越界才报「文件意外结束」。v6（NBS 3.12.0-beta 起，2026-03）字节格式与 v5 一致，仅 `first_custom_index` 由 16→20（新增 4 个内置小号 ID 16-19，Minecraft 26.1 引入）；因目标 MC（1.19.4~1.21.11）的 `note_block` 尚无小号，其音符按未映射乐器回退为 harp（雪块底座），**歌曲信息区会提示「含 N 个小号音符…将回退为 harp 播放」**；自定义乐器区从 ID 20 起、仍按现有映射处理
- 错误区可展开「诊断信息」（JSON），一键**导出诊断 JSON** 文件反馈问题
- 诊断内容全部经 DOM API（`createElement`/`textContent`）渲染，不拼接用户数据到 HTML

## 已知限制

- 目标版本为下拉内 10 档（1.19.4 ~ 1.21.11）；其他版本（如 1.21.1）暂不支持，但文件可尝试在更高版本的 Litematica 中打开（DataVersion 偏低时 Litematica 会跑 DataFixer，对我们使用的古老方块无实际改动）
- `/tick rate` 改变整个世界速度（实体/玩家/昼夜），每次进世界需重新执行；无管理员权限的服务器需服主执行
- NBS 的 velocity/panning/pitch 不参与转换（红石音符盒无法表达）
- 粒子特效依赖用户自有的 `particleex` 模组命令（命令文本逐字写死，仅坐标段由构建时计算的偏移替换，不做 vanilla 选项框约束）；无模组时命令方块执行失败但不影响演奏
- 自定义乐器（ID≥16）默认映射到竖琴，可在设置中改
- X 跨度 >300 格时注意模拟距离（播放可能中断）
