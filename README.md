# NBS2schematic

将 Minecraft NBS 音乐文件（Note Block Studio 格式）转换为「红石音乐」布局的 **.litematic 投影 schematic**（Litematica 投影 mod），摆好后手动铺设总线与开关、接通各链头即可播放。

## 使用方法

1. 双击打开 `index.html`（现代浏览器：Chrome/Edge 80+、Firefox 113+、Safari 16.4+）。页面为**左右分栏**：左侧独立侧边栏 = 音轨池（列表随侧栏高度内部滚动，宽 680px = 340 的 2 倍；侧栏顶栏 ◀ **收起**后侧栏整体隐藏、右侧顶部出现「▶ 展开音轨池」按钮，状态跨歌保留），右侧 = 歌曲信息 / 速度分析 / 车道池 / 普通车道起点布局 / 节奏型参考车道池（含参考车道起点布局窗口）/ 粒子歌词 / 设置 / 生成等全部组件（鼠标滚轮滚动）。**默认字体**（LXGW WenKai Lite，CDN jsdelivr）需联网加载一次，超时自动回退系统楷体链，核心功能完全离线
2. 拖入 `.nbs` 文件（或点击选择）
3. 勾选要转换的声部（默认全选有声部的层，在左侧音轨池）
   - 可选：勾选某声部的**「节奏参考」**复选框 → 该声道每个音符在轨道 0 触发一次粒子特效（见下文「节奏参考声道」），**同时以勾选式并入右侧「节奏型参考车道池」**（默认并入第一条无冲突参考车道、放不下自动新建；也可直接把音轨**拖入**参考车道卡片指定车道）。**勾选只进参考车道池，不再自动在音轨车道池复制一份**；参考声道的行内只保留**「发声」**复选框（默认关 = **在普通轨道也发声**的显式开关：取消 = 普通轨道无盒、零声音（参考车道是纯虚拟参考，不生成任何结构，只剩节奏/音高粒子参考）；勾选 = 把音轨显式并入音轨车道池，普通轨道放真实盒发声；「节奏参考」与「发声」两选项位置固定相邻，勾选前后不移动）；**类型选型（单线式 / MIDI式）在参考车道池中按车道选择**——一条参考车道的全部成员声道共用同一类型，切换类型时成员「发声」状态保持原值（可自由开关；参考车道为纯虚拟参考，粒子恒产生，见下文）
4. 配置车道：把音轨池中的音轨**拖入**车道卡片即分配（音轨数量不限、同一音轨可重复拖入 = 占多个音符盒位齐响更响；点击标签 ✕ 移除；⧉ 复制 = 生成第二条相同链齐响加倍）。每张卡片顶部显示**冲突分析**（合并后同 tick 超 3 位的丢弃数），下方「简并建议」从**名称重复、音符少、乐器类型**三个角度给合并建议 + 无冲突打包方案（一键应用）；面板顶部自动检查**未分配音轨**并给出警告（可一键自动并入）。**节奏型参考车道池**（独立分区）：成员来自音轨池「节奏参考」勾选（勾选式并入）**或直接把音轨拖入卡片**（拖入即登记为节奏参考并入该车道，允许重复拖入占多个盒位齐响），卡片支持 **＋ 新增 / ⧉ 复制 / ✕ 删除 / 标签 ✕ 移除**，同样带冲突徽章，**头部带类型下拉（MIDI式/单线式，作用于该车道全部成员）**；**参考车道是纯虚拟参考（2026-09-07 起不生成任何物理结构）**——只保留假定的 (dz, dy) 起点 + 3 盒位 Z 槽位作粒子锚点几何，可与普通车道任意并排（不参与碰撞校验）；**未勾选「发声」的参考成员标签标琥珀（「（静音）」）+ 分区级 ⚠ 提示**（普通轨道无盒，仅节奏/音高参考；想同时发声请在左侧音轨池勾选其「发声」）；把参考音轨**显式拖入音轨车道卡片**（或勾选其行内「发声」）即让普通轨道放真实盒发声。**音量还原（2026-10-09）**：车道卡片头部「音量还原」复选框（每轨独立 opt-in），勾选后该车道以起点增益为 100 基准、按 velocity 沿 Z 偏移还原响度（依赖「矿车监听」启用，见「音量还原」章节）
5. 在「普通车道起点布局」（车道池紧随其后的独立分区，Y-Z 截面）拖拽各链起点位置（含恒生成的**轨道 0**，琥珀色虚线「0」标记；音轨车道编号 1..n；**单线式参考车道紫色点划线「R1..」标记、可拖**；**起点支持负 Y/Z**，网格生成时整体平移保证产物坐标非负；**Z=0 / Y=0 坐标轴加粗显示**），或用预置模板——**「单行 / 网格 / 放射」三模板以 0 号车道（轨道 0）起点为中心对称排布；「声像」以坐标轴原点 (0,0) 为圆心（2026-10-10 用户定案：声像距离/俯仰语义相对听者（原点），与参考圈、±67.5° 线同心）**，只重排音轨车道（参考车道为纯虚拟参考、位置不受预置影响，MIDI式中心基准在下方「参考车道池」分区内的独立窗口拖动）：单行 = Z 向两侧交替 ±3、±6…（偶数位 +Z 侧）；网格 = 中间行两侧 ±3 起逐行外扩、Y 向上下交替抬升（行距 = 设置区「网格/放射行距」，默认 5）；放射 = 按到中心欧氏距离由近及远取位（Z 步长 3、Y 步长 = 行距，同距 +Z 侧优先）；**声像 = 按 NBS 的 panning/velocity 统计自动排布**（2026-10-06；2026-10-09 改半径 24 圆周、2026-10-10 圆心修正为坐标轴原点）：轨道优先放距坐标轴原点 ≈24 格（半径 24 圆，圆心 = (0,0)，非轨道 0 起点；y 轴数值不限），且优先在**俯仰角 <67°** 的弧段内（10-08 实测俯仰 >67.5° 立体声减弱，圆上 y 轴侧的点贴 67° 边界）；模式可切换：「按声像」= 车道按 panning 均值降序（整数交叉乘）依序占圆周、大 panning 靠 +Z 轴；「按音量」= 方向由 panning 定、响度定序（velocity 均值 ÷ 10 取整，最小 1）、中心车道殿后
6. 查看「播放速度分析」：主链 1 档中继器、游戏内 `/tick rate` 校正命令、跟随播放指引；设置：自定义乐器映射、**MIDI式参考音高步长 sfxPitchStep**（0–8，默认 1，支持小数步进 0.1）、**目标 Litematica 版本**（1.19.4 ~ 1.21.11 十档可选，默认 1.21.11，见下文「多版本兼容」）
7. 点击「生成 schematic」→ 自动**产物自检**（解码刚生成的 NBT 与内存网格逐格比对 + gzip 往返校验，失败不亮下载按钮）→ 检查统计与三视图预览 → 下载 `.litematic`（导入新 NBS 会自动清除旧结果与预览）；生成期间**进度条分段推进**（歌词渲染 → 布局构建 → 打包 → 压缩 → 自检 → 数据包 zip，2026-10-06）+ 阶段文字 + 按钮禁用，失败自动复位；**有参考声道时**生成后额外出现「⬇ 下载粒子数据包 (.zip)」按钮——完整数据包 zip（pack.mcmeta + data/nbs2sfx/…/<tick>.mcfunction），与 .litematic 配套
8. 放入 `.minecraft/schematics/`，在对应 MC 版本（与所选「目标 Litematica 版本」一致）中用 Litematica 加载投影；**有参考声道时**把粒子数据包 zip 解压到 `.minecraft/datapacks/`（游戏内 `/reload`，或开图前放入）
9. 手动铺设总线与开关接通各链头（触发区由用户自铺，见下文「触发区（用户手动放置）」）；播放前按面板提示执行 `/tick rate <R>`（若 R≈20 可跳过），触发播放并跟随链移动

## 电路设计

- **主链**：每 NBS tick 占 2 格 X——中继器格（**恒 1 档**，周期 2 游戏刻，零抖动）+ 音符格。**中继器朝向语义**：`facing` 是**输入侧**（官方 wiki：「from the output side to the input side」，与放置时面向相反），输出朝对面 → 信号流向 +X 的中继器写 `facing=west`（触发区已移出产物，图中所有中继器都在主链，恒 `facing=west`；曾误按「输出方向」写导致整条链断链，validate/smoke 均有逐格朝向断言回归保护）
- **速度模型（NBS 是基准，游戏去适应它）**：主链 1 档中继器周期恒 2 游戏刻/NBS tick（用户游戏内实测校准：音符盒/红石粉 0 延迟）；播放时游戏内执行 `/tick rate R = 2 × tempo` 精确校正（tempo=10 时 R=20 即默认 20tps 无需调整；tempo=5 时 R=10、tempo=8.5 时 R=17）
- **音符格（音符盒导电结构）**：主音符盒放在中继器输出端正前方（被强充能 → 发声 + 导电 + **激活两侧紧挨的第 2/3 音符盒**，三个同刻齐响）；无音符时该位置放红石粉直通传导。音符盒是红石导体（minecraft.wiki 查证），信号不中断
- **底座**：音符盒下方为对应音色方块（harp→雪块、bit→绿宝石块）；雪块主体框架只保留最中心的线，中继器格中心底座恒为雪块（蜂蜜块小节标记已取消——蜂蜜块非满方块，碰撞箱仅 14×14×15，不适合垫中继器）。**防掉落托底**：snare 音色底为沙子（重力方块，会掉落），生成时其正下方自动补一个雪块托住（用户游戏内实测发现）
- **触发区（用户手动放置）**：总线 / 各链下降 tap / 启动开关（按钮/拉杆/压力板）已按用户要求**从产物中整体移除**（用户确认：手动放置）。产物只含各轨道主体（主链中继器 + 音符盒 + 底座 + 轨道 0 顶层导轨）；**每条链的链头是 X=0 处的 1 档中继器，其输入端（-X 侧）留空**，用户自铺总线（如 Z 向红石粉 + 下降/水平线）从任意高度接通各链头输入端，开关自便（拉杆/按钮/压力板等）。历史设计（纯红石粉 Z 向总线 + 插座候选搜索 + 自然延迟 |zc−zStub|+k+1、多车道首音先后响起）仍可直接照搬实现，不再内置
- **音高**：NBS `song_key` → note_block `note` 线性绝对音高 `note = key − 33`（key 33=F#3→note 0、45=F#4→note 12、57=F#5→note 24，有效区间恰好覆盖音符盒 0-24 全音域；NBS Studio 官方红石导出即此公式与 33-57 范围）；key 越界的音（常见于微音移调）跳过并计数，主位以红石粉代位保通路
- **车道**：音轨池（NBS 声部）**拖拽**分配给车道池中的任意车道（多对多）；**音轨数量不限**，卡片顶部实时显示冲突分析（同 tick 超 3 个音符盒位时丢弃并计数）；同一音轨可在同一车道重复出现（占多个音符盒位，同 tick 齐响 = 双倍音量）；**⧉ 复制**车道 = 第二条独立链播放相同音轨（齐响加倍）；每条车道 = 一条中继器链 + 主/第2/第3 三个音符盒位
- **页面布局**：左右分栏——左侧独立侧边栏放**音轨池**（勾选/参考/发声 + 拖拽源，列表随侧栏高度内部滚动），**可折叠**（侧栏顶栏 ◀ 收起 = 侧栏**整体隐藏**，右侧顶部出现「▶ 展开音轨池」按钮恢复，**sticky 钉在右侧滚动区顶部、不随滚轮划走**；展开 = 680px（340px 的 2 倍）；折叠状态存全局 UI 键 `nbs2schematic:ui`，跨歌保留）；右侧为歌曲信息 / 速度分析 / 车道池 / **普通车道起点布局** / **节奏型参考车道池**（含其分区内的参考车道起点布局窗口）/ 设置 / 生成等全部组件（滚轮滚动）；窄屏（≤900px）退化为上下堆叠 + 整页滚动（折叠 = 隐藏音轨池区）
- **参考车道池（节奏型参考车道池，纯虚拟参考）**：独立网页分区，类车道池卡片（＋ 新增 / ⧉ 复制 / ✕ 删除 / 成员标签 ✕ / 冲突徽章 / **类型下拉**），成员两种进入方式：①音轨池「节奏参考」**勾选式**并入（默认第一条无冲突参考车道、放不下自动新建，与音轨车道勾选语义一致；「全选/全不选」时整体重建，每 3 条参考成员一车道，新建车道默认MIDI式）；②**拖拽式**——左侧音轨池的音轨直接拖入卡片投放区（拖入即登记为节奏参考声道并入该车道；允许重复拖入同一车道（同 tick 多成员齐响，触发粒子只取主位、每 tick 每车道至多 1 行）；同一音轨已在其他参考车道时移入目标车道）。每条参考车道 = 一个**虚拟的假定车道**（起点 + 主位锚点），**2026-09-07 起不生成任何物理结构**（无中继器/雪块/音符盒/命令方块），只作单线式粒子的锚点几何；**网格尺寸只由真实链（轨道 0 + 音轨车道）决定**，参考车道虚拟起点即使超出网格范围也不扩格；**与普通车道可任意并排**（不参与碰撞校验）。**类型选型按参考车道**（存 `lane.type`，构建侧按成员所在参考车道取类型）：一条车道的全部成员声道共用同一类型——成员 refLayers 类型跟随车道、sound 保持原值（切单线式**不再强制发声**）；同一成员分属多条车道时按「绑定优先」合并。复制车道连同类型一起复制。**「发声」= 普通轨道是否放真实盒**：未勾选的参考成员标签标琥珀（「（静音）」）、分区级 ⚠ 提示、拖入时生成状态行提示；**粒子恒产生，不受「发声」影响**（参考意义）。参考车道默认起点按类型分流（2026-09-07 独立中心可拖后）：**MIDI式**缺省 (0,0)（粒子中心基准 = 轨道 0 CB 位置，多车道 (0,0) 重叠 = 粒子有意叠放，合法）；**单线式**在音轨车道右侧（`dz = i×3 + 6`，避开音轨车道 `i×3+3` 与轨道 0 的 Z=0；预置模板只重排音轨车道，见上）
- **默认轨道 0**：恒生成于车道池顶部（固定卡片「轨道 0（默认）」，不可删除、不分配音轨）。物理上是一条**真实的无音符中继器链**（与普通无音符车道结构完全相同：中继器链 + 雪块底座，链头同样留空待手动接总线，无音符），唯一特征是**顶层导轨**：在 y = 起点 Y + 2 处沿 +X 铺 1 高 × 1 宽雪块轨（与主链同长，x=0..xMax−1，只写空气格不覆盖其他结构），每 32 格替换 1 格为 `minecraft:ochre_froglight`（赭黄蛙灯，ID 经 Mojang 官方 1.21.11 server.jar 查证），即 X=32, 64, 96…（链头 X=0 保持雪块）。蛙灯与雪块同为不透明满方块、无红石功能，纯装饰标识。**节奏参考声道的粒子命令方块统一放在轨道 0**（该 tick 段主位底座，见下文「节奏参考声道」），是整张图的粒子触发链。起点在布局编辑器中可拖拽（默认 Z=0，**可拖到负 Y/Z**）；为轨道 0 让出 Z=0，音轨车道 1..n 的默认起点整体右移 +3（`dz = i×3 + 3`，i 从 1 起）；**空车道池也可生成**（产物 = 仅轨道 0 链，总线/开关由用户手动放置）
- **负起点支持**：任意链（含轨道 0）起点允许负 Y/Z。产物网格整体平移保证非负——`yOffset = −min(0, 各链 yb)`、`zOffset = 1 − min(0, 各链 zc)`（**只在最小值确为负时平移**，全非负起点时退化为旧值 yOffset=0/zOffset=1，产物与旧版一致）；第 3 音符盒占 zc−1 与负起点共同决定 zOffset；单线式粒子偏移是两链坐标差，平移对其无影响；snare 沙子托底按网格 y≥1 扫描补雪块，平移后凡底座行下方有空间（非最低链）照常托底（最低链底座在网格 y=0、下方无空间，与既有全非负行为一致）
- **未分配检查**：池中未被任何车道引用的音轨不会出现在 schematic 中，面板顶部自动警告并列出编号，「＋ 自动并入」逐条尝试无冲突并入现有车道（放不下则新建车道）
- **布局编辑器（双窗口，2026-09-07 参考车道虚拟化后）**：Y-Z 截面画布 ×2（滚轮缩放、拖拽平移、点击选中、方向键微调，Shift = 5 格大步）——**主窗口**管轨道 0（琥珀虚线「0」，不可拖）+ 音轨车道（实线，按主导乐器色）+ **单线式**参考车道（紫色点划线「R1..」，**可拖 = 虚拟盒位锚点**，直接决定绑定粒子行偏移）；**MIDI式**参考车道以半透明虚线背景显示、不可拖（其粒子中心基准在参考窗口拖）；**参考车道独立窗口**（**MIDI式**参考车道紫点划线「1..n」，**可拖 = 粒子中心基准**（其 start 即MIDI式粒子的中心平移量，缺省 (0,0) = 轨道 0 CB 位置）；**单线式**参考车道紫色半透明背景（kind `ref-bg`，本窗口不可拖——到主窗口拖）；普通车道 + 轨道 0 灰背景不可拖）。两窗各自独立缩放/平移；**Z=0 竖轴 / Y=0 横轴加粗提亮**（2px、#4a5568），轴标签 Z → / Y ↑ 加大加粗，便于定位。起点重叠 = 错误（阻断生成，**只校验主窗口内轨道 0 + 音轨车道之间**——参考车道纯虚拟不参与碰撞，与普通车道同位不报错；**ref 窗口恒不校验**——MIDI式中心 (0,0) 默认互相重叠 = 粒子有意叠放，合法）、间距 <3 格 = 警告（串扰提示）。「缩放到全部」自适应视图
- **简并建议**：从名称重复（含相似名，如 Main/Main2 归一归组）、音符少（≤10 可并入其他车道）、乐器类型（主导乐器相同）三个角度给出合并建议；「无冲突打包」贪心算法**名称重复优先**（同名归一组整体前置、组内音符少先；放置时优先聚入已含同名成员的车道，容量允许下同名成员绝不拆散到多余车道），随后常规简并（常见乐器先 → 音符少先；加入车道需所有 tick ≤3 位）给出最少车道方案，可一键应用
- **播放速度**：`/tick rate` 为 vanilla 命令（Mojang 官方 1.20.3 更新日志查证，1.21.11 可用，需管理员权限，范围 (1, 10000)，改回 `/tick rate 20` 恢复；fabric-carpet 1.4.123+ 已移除自有 /tick）

## 跟随播放（音符盒可听范围约 48 格，链会沿 +X 推进）

链推进速度 = 2 × tempo 块/秒（每 tick 恒 2 格，面板会显示本曲数值）。产物为**各轨道主体**（不含触发区——总线/开关由用户手动放置；不含跟随装置——骑猪跟随装置已按用户要求移除）：

- **tempo ≤ 5**（速度 ≤ 10 块/秒）：创造飞行跟随（约 10.9 块/秒）——F3 将 facing 对齐 0° 后按住 W 直飞
- **更快**：游戏内自建骑乘 + 命令方块 tp——召唤并骑乘带 tag 的猪，循环命令方块每游戏 tick 前移 2/D 格：`/execute as @e[tag=rmr,type=pig] at @s run tp @s ^0.5 ^ ^`（步长按面板提示），与链精确同步

## 音量衰减（音符盒 48 格线性衰减）

| 距离 d | 增益 | 距离 d | 增益 |
|---|---|---|---|
| 0 格 | 100% | 36 格 | 25% |
| 12 格 | 75% | 42 格 | 12.5% |
| 24 格 | 50% | 48 格 | 0%（可听边界）|

## 音量还原（每轨 opt-in：以起点增益为 100 基准，按 velocity 沿 Z 偏移还原音量）

音符盒引擎恒满音量，NBS 的 velocity（0–127）无法直接用音符盒表达——本模式把「音量」映射为「距离」：**轨道起点增益 g0 = 100 基准**，每个音符按 velocity 反解盒的绝对 Z 位置（v<100 → +Z 更远更轻；v>100 → −Z 更近更响），**主链（红石线）自动重定位**到该轨全部音符所需位置的**中位数**，使 ±15 格红石分支预算覆盖整轨音量跨度。勾选车道卡片上的「音量还原」开启（每轨独立）。

**依赖矿车监听**：监听者 = 布局原点行走行的矿车（增益参照物，见「矿车监听系统」），未启用监听时 generate 报错中止。

**公式**（zc = 车道起点 Z、yb = 起点 Y，均取监听让位后值）：

```
g0      = max(0, 1 − hypot(zc, yb+1)/48)      # 起点增益 = 100 基准
target  = g0 × velocity/100                    # 目标增益
reqZ(v) = √((48×(1−target))² − (yb+1)²)        # 反解盒绝对 z（距离 ≤ yb+1 时回 1）
dz      = round(reqZ(v) − zLine)，截断到 [−15, +15]   # 相对主链的 Z 偏移
```

**放置语义**：

- dz=0（≈100 侧）→ 盒放**主位**（增益恰为 g0，100 精确表达）；dz≠0 → 主位红石粉 + **纯粉分支**沿 Z 到末端放盒（红石粉只能被红石粉驱动——[红石充能反编译实锤](ref/redstone_power.md)，盒不能驱动分支，分支必须纯粉链）；
- **每 tick ≤1 盒**：和弦保留 velocity 最高者、其余丢弃并记明细；velocity=0 丢弃；分支格被占用 → 丢弃该音不覆盖；
- 偏移超 ±15 截断并记明细（偏音量 = 目标 vs 边界增益）；
- 主链重定位：跨度 ≤30 → 中位数（任一音偏移 >15 时回退 30 跨度中点）；跨度 >30 → 中点并夹取到 [z0−15, z0+15]（**100 侧优先**，z0 = v=100 的 z）。

**起点增益支持范围**（yb=0 时 `start.dz` → g0；yb>0 时垂直分量更大、可表达上限随之降低）：

| start.dz | g0 | start.dz | g0 |
|---|---|---|---|
| 1 | 97.1% | 15 | 68.7% |
| 3 | 93.4% | 24 | 50.0% |
| 6 | 87.3% | 36 | 25.0% |
| 12 | 74.9% | 48 | 0%（静音边界）|

**布局图参考线**：main 与参考车道窗口画布一致绘制**琥珀色虚线** `y = ±tan(67.5°)·z`（过原点，标签「±67.5°」）+ 12/24/36/48 可听范围参考圈——玩家对盒的俯仰角 >67.5° 时立体声明显减弱（2026-10-08 游戏内实测），音量还原的 Z 偏移应尽量落在两线之间。

**消失型机制**：每个参考音符在 `t−N` tick 生成一行 `particleex conditional` 命令（#Cube 条件立方体原型，命令除**坐标段**、**寿命字段**与**组位（可选，见「粒子组名」）**外逐字写死），**寿命字段 = 实际提前量 N 由构建自动计算**（替换原型第 11 个字段 `20`）→ 粒子常驻 `t−N → t` 区间、恰在演奏 tick t 自然消亡（与音符激活同 tick；多车道/多音符寿命独立互不干扰）。**保险移除（2026-10-10）**：生成行组位并入专用保险组 `nbs2sfx_vanish_<t>`（与用户组名以 `|` 并存，模组源码确认按 `|` 分拆注册/移除），演奏 tick t 的 function 追加 `particleex group remove nbs2sfx_vanish_<t>` 兜底清除——age 正常时粒子已自灭（no-op）、异常残留时保险生效；演奏 tick 因此恒有行（不再空 tick 回退）。**钳位**：歌曲开头提前量不足（`t−N < 0`）→ 生成落 tick 0、寿命 = t（实际提前量）；`t=0` 无提前量 → 跳过。生成行一般落在无参考音符的 tick → 用该 tick 的轨道 0 命令方块自持 function/CB（`sfxVanishTicks` 支撑）。锚点与触发型相同（单线式 = 车道虚拟主位；MIDI式 = 车道 start 基准，**MIDI式逐音符叠加音高展开** `(key−33−center)×sfxPitchStep`（2026-10-10，center 与连接线同源 = 距车道音高中位数最近的 F# 系音）——和弦多音 → 多框按音高铺开，不再全叠在 start 一点）。

**背景型机制（2026-09-10）**：NBS 格式 1 拍 = 18.125 tick（格式常数，与 tempo 无关）；小节长 = 拍号 × 18.125 四舍五入（`sfxBarLen`，4/4 → 73、3/4 → 54，拍号非法按 4 拍兜底）。生成块在主循环前运行：对每小节 tick `t = 0, barLen, 2×barLen, …`（< nTicks），遍历全部参考车道（**遍历 chains 而非 sfxLaneEvents**——无音符成员的参考车道也产行），`effects` 含 `background`（缺省 = 含）且模板非空的车道各 push 1 行（`lane.sfxParams.background` trim 后逐字）。产行 tick 并入 `sfxBackgroundTicks` → 该 tick 无音符盒/无其他粒子行时仍放轨道 0 CB（自持 function），与 `sfxEntries` 合并判定 `isSfxTick`；某背景 tick 最终无任何粒子行（车道取消勾选/模板清空）→ 同空 tick 回退雪块。行序：消失行最前、**背景行次之**、绑定/独立/连接线随后。统计 `sfxBackgroundNotes` 在状态行展示（「背景型 N」）。

**连接型线段（已实现）数学**：按**参考车道**连，车道内任一成员发声的 tick 构成演奏 tick 序列，相邻演奏 tick A(t_A)→B(t_B)，Δt = t_B − t_A。**端点几何（2026-09-10 用户实测修正为真空间斜线）**：MIDI式 A = t_A 音的粒子中心 (0, start, z_A)、B = t_B 音的粒子中心沿链前移 (2Δt, start, z_B)——主链每 NBS tick 恒 2 格（与单线式「沿链 +X 平移 dt×2 格」同约定），笔尖末点仍恰在 t_B 抵达 B 的粒子中心，无缝衔接；同音高对 (z_A=z_B) 退化为沿链 +X 水平线；**旧实现 B 端与 A 同 X=0 → 线段平行 Z、垂直于链传播方向，视觉错误**。单线式与音高无关 → 端点简并为车道中间槽位、A=(0, yMid, zMid)、B=(2Δt, yMid, zMid)。L = |B−A|，N₀ = ⌈L/0.1⌉（固定 0.1 格点距为密度上限），`cpt = max(1, ⌈(N₀+1)/(2Δt+1)⌉)`、`P = (2Δt+1)·cpt`、`step = 1/(P−1)`——模组 `tickpolarparameter` 任务**每游戏 tick 生成一次**（客户端任务由 tick 事件驱动、自调度下一游戏 tick；**命令第 10 字段是 `cpt`（每游戏 tick 点数），不是总点数 `P`**：源码 `ParticleUtil.TickParticleTask.run` 为 `for (i=0; i<cpt && t<=end; t+=step)`，每游戏 tick 至多生成 `cpt` 点、`t>end` 才停并在 `t<=end` 时自调度下一 tick；2026-09-12 修正——此前误传 `P` → 整条线在 t_A 一个 tick 内全部生成、粒子不「沿 A→B 依次显现」；**2026-09-25 用户游戏实测再修正**——旧公式 `P=(Δt+1)·cpt` 把 NBS tick 当游戏 tick，实际生成速度 2×（笔尖领先链头），现按 1 NBS tick = 2 游戏 tick 计：总点数 `P` 恰跨 ⌈P/cpt⌉ = **2Δt+1 游戏 tick**（= Δt 个 NBS tick）铺完，末点 k=P−1 生于 t_A+⌊(P−1)/cpt⌋ = t_A+2Δt（游戏 tick）= **t_B**（NBS tick 时刻），笔尖速度 = L/(2Δt 游戏 tick) = **1 格/游戏 tick，与链传播同速**，与 B 的触发型/音符盒激活同 tick 无缝衔接；实际点距 = L/(P−1) ≤ 0.1。方向用球坐标（模组约定 `dx=dis·cos(s2)·cos(s1), dy=dis·sin(s2), dz=dis·cos(s2)·sin(s1)`）：φ=atan2(dz,dx)、θ=atan2(dy,√(dx²+dz²))、dis=L·t，t∈[0, 1+½step]（半采样点余量兜浮点累加漂移，B 端由触发环接住）。斜线恒含 +X 分量 → |φ|<π/2（纯 Z 线仅当 Δt=0；实际相邻 tick 恒 Δt≥1，不再出现垂直于链的线段）。`age = m`（每粒子自出生起存活 m 个**游戏 tick**，用户手输；m ≥ 2Δt（游戏 tick）= 到达后整线停留再消融，m < 2Δt = 彗星尾）。**litematic 零改动**（纯数据包函数行增量，行落 t_A）；L < 0.05（A≈B 完全重合）跳过——真空间斜线下同音高对 L=2Δt≥2 不再触发该跳过（仅保留兜底）。

**弧线风格（2026-09-28）**：车道级 `style='arc'` 时连线改用**二次 Bézier 抛物线拱 + 轻阻力**（命令变体 `particleex tickparameter`，直角坐标 x/y/z 直接由表达式给出，不走球坐标）：
- **几何**：相对 A 原点 `Q(s) = s·(2c + s·k)`，c = C−A、k = B−2C，**C = 弦中点 + 2·lift·L·ŷ** → 顶点偏离弦高 = **lift×L**（垂直向上拱起；lift=0 退化为直线）。p=1 对称情形可化为标准抛物线 `y = h·4·s(1−s)`。
- **阻力感**：重参数化 `s(t) = 1 − (1−t)^p`——s(0)=0、s(1)=1，**端点仍恰在 t_B 抵达 B（无缝衔接不变式保留）**；ds/dt(0)=p 快、ds/dt(1)=0 慢 → 开头快、结尾慢（p=1 = 匀速无阻力，越大近 B 端越慢）。表达式串用 `pow(abs(1−t),p)`：abs 兜 t>1 溢出点（`end = 1+½step` 时 (1−t)^p 负底数非整数幂 = NaN）。
- **点数预算**：时间域速度峰值 = p → `N₀ = ⌈p·arcLen/0.1⌉`（arcLen = 64 采样折线弧长，p=1 时 = 直线 ⌈L/0.1⌉ 公式）；cpt/P/step 公式与直线完全共享（`sfxConnectPacing`）。
- **表达式串**（构建时把系数全部算好嵌入字面量，运行时每点 = 2 次 pow + 若干乘加，无三角/开方）：`(x,y,z)=((1-pow(abs(1-t),p))*(2*cx+(1-pow(abs(1-t),p))*kx), …三轴同构…)`——语法只用模组引擎生产在用/源码实锤元素（矩阵赋值与速度表达式 `(vx,vy,vz)=` 同构、四则、`Math.pow`/`Math.abs`），不引入局部变量/多语句；表达式含空格/括号等，命令里须**双引号包裹**（与 `tickpolarparameter` 的 `"s1,s2,dis=…"` 同约定；2026-10-04 游戏日志实锤：无引号时 brigadier 只消费 1 个 token，报「期望空格」致整函数加载失败）。

**和弦（同 tick 多音）与连线配对**：NBS 格式每 (声道, tick) 至多 1 音（`layer_delta=0` 即该 tick 结束、同 tick 内层号严格递增）→ 同声道叠多音不可编码；和弦 = **同一参考车道多个成员声道同 tick 齐响**（跨声道，车道最多 3 成员 = 最多 3 音和弦）。触发型每音一行粒子；MIDI式连接线端点按和弦配对（`sfxChordPairs`）：**Δt ≤ 32 tick** 时 1:1 最近邻优先、数量不齐时落单音就近挂靠（允许 1对3/3对1）；**Δt > 32 tick** 严格 1:1、落单不连。单线式与音高无关，端点简并为车道中间槽位、沿链 +X 方向，每演奏 tick 对只一条线。

- 粒子命令基础文本固定（用户提供的 `particleex polarparameter …` 模组命令，逐字写死不做修正），**仅坐标段 `~ ~2 ~` 被替换为计算偏移 `~dx ~dy ~dz`**，命令其余部分（粒子/颜色/速度/表达式/寿命）保持原样；**单线式行支持按车道模板覆盖**（见上方「车道模板参数编辑」：`lane.sfxParams` 5 字段，坐标段同样按计算偏移替换；MIDI式主命令恒用默认命令，5 字段模板不作用于独立行）；**可选组名**替换尾参末 token `null`（仅当其为 `null` 时，见「粒子组名」）；**可选追加命令**逐行原文、坐标段同偏移替换、紧跟主行，**单线式绑定行与 MIDI式独立行均生效**（**缺省 = 内置 conditional 默认命令**，见上方「触发型追加命令」）
- 命名空间固定 `nbs2sfx`；mcfunction 文件名 = tick 编号
- **使用**：zip 内容解压到 `.minecraft/datapacks/`（游戏内 `/reload` 或开图前放入），依赖用户自有的 `particleex` 模组命令；与 .litematic 版本头一致的目标版本对应正确的 pack format 与目录名（1.19.4~1.20.x 用 `functions/`，1.21+ 用 `function/`）
- pack format 数值经 Mojang 官方 jar 字节码查证：1.19.4=13 / 1.20.1=15 / 1.20.4=26 / 1.21=48 / 1.21.3=57 / 1.21.4=61 / 1.21.5=71 / 1.21.8=81 / 1.21.10=88 / 1.21.11=94.1；25w31a 起 `pack_format` 被 `min_format`/`max_format` 取代（1.21.11 jar 确认旧字段仅触发 deprecated 警告仍被解析，故新写法按目标版本自动选择）

## 自定义乐器 · 资源包 playsound

NBS 的自定义乐器（导入的 .ogg 声音文件，ID ≥ defaultInstruments：v4/v5 从 16、v6 从 20、v0 从 10）默认只能映射到 16 个内置音色近似播放。可在**设置区**为每个自定义乐器单独填一个**资源包声音 ID**（`namespace:sound_id`，如 `minecraft:block.portal.trigger`），真实音色由 `playsound` 命令方块按 tick 精确触发：

- **配置语义（2026-09-29 命令方块直写）**：配置了 sound ID 的乐器，其音符**不放音符盒**——代位格导电层放**红石粉**（命令方块**非红石导体**，放导电层会断主链，故红石粉保传导），底座**统一雪块**；**命令方块放代位格正上方一格**（信号层红石粉在机制正上方按红石规则激活 → 该 tick 执行），第2/3位代位同样各自放一个（声音在各自精确位置播放）；统计「命令方块 N（节奏参考 + playsound）」与「playsound 代位 N」（状态行 + 生成摘要）。**留空 = 不生成 playsound**（走内置音色映射，产物与未配置逐位一致）
- **声音 ID 规则**：`namespace:sound_id`，仅允许字母/数字/`_`/`.`/`-`、冒号恰好 1 个、无空格（`sfxNormSoundId` 白名单校验，非法拒写并回填旧值）；ID 完全由用户自定义，须与**自备资源包**中实际登记的声音一致（`assets/<namespace>/sounds.json` 的键 + `pack.mcmeta` 声明的 namespace；用现有 namespace 如 `music:` 时注意勿覆盖原文件）。输入框示例 `minecraft:block.portal.trigger` = 原版末地传送门触发音（用户游戏内实测确认；无需资源包即可试听）
- **生成的命令**（写进命令方块 TE 的 `Command` 字段，**无斜杠**，不进 `<t>.mcfunction`）：`playsound <soundID> master @a ~ ~ ~ <vol> <pitch>`——`@a` 全体玩家、`~ ~ ~` = 该 CB 本体位置（代位格正上方），声音从代位音符盒位置向全体玩家播放；`vol = velocity/100`（NBS 0–127 → **0.00–1.27**，**音量 >1.0 的游戏内行为未校准**——按 NBS 原值输出，若觉得太响需自行改模板或后续加钳位）；`pitch = 0.5 × 2^((key−33)/12)`（NBS 播放公式，key 33→0.5、45→1、57→2）
- **不生成 playsound 的情形**：sound ID 未配置/非法、key 越界（16 个内置音高域之外，与音符盒代位同判：红石粉 + 雪块、无 CB）；代位格照放、计数照记
- **零回归**：未配置任何 sound ID 时产物逐位不变；旧存档无 `soundIdMap` 键按空表处理；数据包 zip 只承载粒子 function 行（有参考声道才生成）——playsound 不再进 zip（CB 在 .litematic 内）

## 粒子歌词（LRC → 粒子歌词显示，2026-10-06）

NBS 格式没有歌词字段，歌词在**「粒子歌词」section**（参考车道池之后、设置之前）独立导入：把一句句歌词渲染成整行 PNG 字库、随数据包 zip 导出，游戏内由 `particleex image` 命令逐句生成粒子显示（依赖 `particleex` 模组，与节奏参考声道同族）。

- **导入**：「选择 LRC/文本」文件或 textarea 粘贴，点「解析」生成句列表（每句一行：起始/结束 tick 输入框（title 显示换算秒）+ 文本输入 + ✕ 删除；「＋ 添加句」手动增补）。**LRC**：`[mm:ss.xx]` 时间戳，秒→tick = round(sec × tempo)，一行可多时间戳（多句同文本），`ar:`/`ti:` 等元数据行跳过；**纯文本**（无时间戳）：按非空行均分全曲长。缺省 end = 下一句 start，末句 end = 曲长。重叠/超曲长/空文本/时间非法只提示不阻断
- **设置**：**字体源**（CDN LXGW WenKai Lite（SIL OFL，jsdelivr webfont）/ 系统楷体链 / 本地上传 ttf·otf（FontFace 运行时加载，**不持久化**——刷新后需重传）；select 旁实时渲染「我的世界」样例供预览；CDN 加载 5s 超时自动回退系统楷体链并在生成摘要提示）、**字号**（16/24/32/48/64，缺省 32）、**字距**（像素，缺省 2）、**每行字数**（自动换行，缺省 8）、**粒子名**（缺省 `minecraft:end_rod`）、**旋转**（偏航 0/90/180/270°，缺省 0°）、**俯仰**（0/90/180/270°，缺省 0°；90° = 文字躺平朝上；朝向以游戏实测为准）、**歌词位置**（布局编辑器第三窗口「歌词位置」，Y-Z 截面拖拽「歌词中心点」，缺省 (0,3,0)）
- **渲染**：每句按每行字数分行，每行 canvas 渲染（白字透明底）→ 按不透明边界裁剪为整行 PNG（`lyric/s{句序号04d}_l{行}.png`，文件名 ASCII，与命令一一对应）；canvas 尺寸上限守护（2000×1000，超宽行告警跳过）
- **命令**（每行一条，写入该句**起始 tick** 的 `<t>.mcfunction`，18 token）：
  `particleex image <粒子> <X> <Y> <Z> <path> 0.03125 <pitch> <rotate> 0 not 10 0 0 0 <age> null 1 null`
  ——scaling 固定 1/32 = 1 格/32px；`<pitch>` = 俯仰（xRot，0-3）、`<rotate>` = 偏航（yRot，0-3），**命令文本按 90° 步进角度序列化**（档位 1→90°、2→180°、3→270°；模组 RotateArgumentType.parse 要求 90 的倍数，内部再 /90 存 0-3）；flip 恒 `not`（枚举词 not/horizontally/vertical，数字会被 parse 拒绝）；X = 位置.x − 行宽/2（行水平居中）、Y = 位置.y + 行偏移（行高 = 字号/32×1.2，句内多行以中心垂直堆叠）、Z = 位置.z；**age = (end−start)×2 游戏 tick**（1 NBS tick = 2 游戏 tick）到期**模组端自动消失**（`setMaxAge`，模组源码实锤）→ 句末**无 remove 行**；group null。起始 tick 轨道 0 主位放底座命令方块（`function nbs2sfx:<t>`，与参考声道同一套 CB 支撑）
- **数据包**：zip 条件放宽为「**有参考声道或有歌词**」——纯歌词（无参考声道）也产 zip（pack.mcmeta + 歌词 function + PNG 条目 `data/nbs2sfx/lyric/*.png`，二进制条目，STORE 零依赖自写写入器 + CRC32）
- **部署**：从数据包 zip 取 `data/nbs2sfx/lyric/` 目录**整体复制到 `.minecraft/particleImages/lyric/`**（模组 image 命令读客户端本地 `./particleImages/` 相对路径，支持子目录，按 (文件, scaling) 缓存），与 datapacks 部署相互独立
- **持久化**：导入的歌词（`lyrics`，tick 整数）与设置（`settings.lyric`）进 per-song 载荷（可选键，旧存档无此键 = 无歌词，产物逐位不变；v=2 不变）；字体文件不持久化
- **零回归**：无歌词时 zip/litematic 逐位不变（旧条件仍主导）

## 状态持久化

- 车道分组、起点位置（含轨道 0）、**参考车道池（refLanes，含每车道类型 `type`、特效勾选 `effects`、特效模板 `sfxParams`（触发 5 字段 + 可选组名 + 连接结构化对象（含可选组名） + 消失结构化对象（含可选组名） + 背景模板文本）；旧存档无这些字段 → 空池/全选/默认命令）**、音轨勾选、**参考声道状态（refLayers，值为 `{type:'bound'|'independent', sound}` 对象；恢复时成员类型跟随其所在参考车道）**、**歌词（`lyrics` 句数组，tick 整数；`settings.lyric` 字体/字号/位置等，见「粒子歌词」）**、设置（目标版本 / 自定义乐器映射 / **sfxPitchStep**）自动保存到 `localStorage`，key 为 `nbs2schematic:v1:<FNV-1a 哈希(文件名:大小)>`——同名不同内容的 NBS 不会误恢复
- **触发型命令预设库**（2026-09-10）存**独立全局 key** `nbs2schematic:sfxpresets`（JSON 数组 `[{name, params}]`，跨歌保留、不随歌曲切换清空）；一个预设 = 触发型 5 字段 + 可选组名（`normSfxParams` 校验后才入库）
- 变更点（勾选/参考/类型/发声/拖拽/复制/删除车道、预置布局、设置修改）防抖 300ms 落盘；重新打开同一首 NBS 时自动恢复并在状态行提示「已恢复上次编辑状态（时间）」；旧存档无 refLayers 字段时按无参考处理，**旧 bool 值（true/false）自动迁移为MIDI式**；**载荷版本 v2（2026-09-07 独立中心可拖）**：v1 的MIDI式 start 是自动排布占位（i×3+6）且旧公式粒子恒在原点，恢复 v1 存档时MIDI式 start 重置为 (0,0)（产物逐位不变），单线式 start 原样保留；v1/v2 载荷均可加载
- 存储不可用（隐私模式/无头环境）时静默降级，不影响主流程
- **自动重建会重置起点语义**：「全选 / 全不选 / 自动分配 / 应用打包建议 / 加载新 NBS」触发整体重建，起点按车道下标 `dz = i×3 + 3`（音轨车道）/ `dz = i×3 + 6`（参考车道）重排（为轨道 0 让出 Z=0；轨道 0 自身起点不受影响）；单个音轨的勾选/取消勾选走**增量增删**（保留现有车道分组与起点，勾选时优先并入第一条无冲突车道、否则新建，取消勾选后空车道保留、可再拖入音轨复用；参考勾选同理，勾选式并入参考车道池）

## 错误诊断

- NBS 解析失败时报**字节偏移**（`文件意外结束 ｜ 字节偏移 N/总长 M`）与**已解析部分**统计（层数/音符数/自定义乐器数），便于定位损坏位置
- **格式嗅探 + 规模上限**：NBS 是无魔数裸二进制，解析前做头部启发式校验——版本号仅接受 v0（旧格式）/v4/v5/v6，声部数 ≤4096、音符数 ≤200 万、文件 ≤256MB（loadFile 前置拒绝）；选错文件（.txt/随机二进制）会提前报「不是有效的 NBS 文件」并提示确认文件类型，而非硬解到越界才报「文件意外结束」。v6（NBS 3.12.0-beta 起，2026-03）字节格式与 v5 一致，仅 `first_custom_index` 由 16→20（新增 4 个内置小号 ID 16-19，Minecraft 26.1 引入）；因目标 MC（1.19.4~1.21.11）的 `note_block` 尚无小号，其音符按未映射乐器回退为 harp（雪块底座），**歌曲信息区会提示「含 N 个小号音符…将回退为 harp 播放」**；自定义乐器区从 ID 20 起、仍按现有映射处理
- 错误区可展开「诊断信息」（JSON），一键**导出诊断 JSON** 文件反馈问题
- 诊断内容全部经 DOM API（`createElement`/`textContent`）渲染，不拼接用户数据到 HTML

## 已知限制

- 目标版本为下拉内 10 档（1.19.4 ~ 1.21.11）；其他版本（如 1.21.1）暂不支持，但文件可尝试在更高版本的 Litematica 中打开（DataVersion 偏低时 Litematica 会跑 DataFixer，对我们使用的古老方块无实际改动）
- `/tick rate` 改变整个世界速度（实体/玩家/昼夜），每次进世界需重新执行；无管理员权限的服务器需服主执行
- NBS 的 velocity/panning/pitch 默认不参与**方块**转换（红石音符盒无法表达）；「预置：声像」按车道 panning/velocity 统计自动排布 Z、「音量还原」按 velocity 沿 Z 偏移还原响度（均为 opt-in，不改变默认产物，见使用方法第 4/5 步与本页「音量还原」章节）
- 粒子特效依赖用户自有的 `particleex` 模组命令（命令文本逐字写死，仅坐标段由构建时计算的偏移替换，不做 vanilla 选项框约束；触发型可在参考车道展开面板按车道覆盖为自定义模板）；无模组时命令方块执行失败但不影响演奏
- 自定义乐器（ID≥16）默认映射到竖琴，可在设置中改
- X 跨度 >300 格时注意模拟距离（播放可能中断）
