# 规划：项目设置导出/导入（含 NBS 文件）

> 日期：2026-11-07 · 状态：**待用户确认后实施**
> 目标：把「导入 NBS 后做的全部项目设置」与 NBS 文件本身打成**一个可移动的工程文件**，实现换机 / 换浏览器 / 分享 / 归档不丢配置。

---

## 1. 现状

| 项 | 现状 |
|---|---|
| 设置存储 | `localStorage`，key = `nbs2schematic:v1:<fnv1a32(文件名:字节数)>`（[index.html:3377](../../index.html)） |
| 内容 | `selectedLayers` / `refLayers` / `lanes`+`volRestore` / `lane0Start` / `refLanes`（type/start/effects/sfxParams）/ `lyrics` / `settings`（targetVersion、乐器映射、soundIdMap、sfxPitchStep、listener、lyric）
| 版本 | 载荷 `v: 2`（v1 兼容读取，v1→v2 有迁移规则） |
| 可移动性 | **无**。清浏览器缓存 = 全部丢失；换机 = 从零重配 |
| NBS 原文件 | `AppState.fileBytes` 在内存里（[index.html:3317](../../index.html)），只在当前会话有效 |
| 已有下载 | `.litematic` / 粒子 zip / JSON 调试包，**均不含设置** |

## 2. 方案选型

| 方案 | 形式 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 单文件 ZIP 工程包 | `.nbsproj`（实为 zip）内含 `song.nbs` + `project.json` | 一个文件搬全部；NBS 原始字节无损；可直接分享 | 需自写 zip 写入器（**已有**，粒子数据包在用）+ 读取器（**需新增**，无依赖解压） | ✅ **推荐** |
| B. 单 JSON | `.nbsproj.json` 内嵌 NBS base64 | 读写简单（JSON + base64） | base64 膨胀 33%；大 NBS（MB 级）内存翻倍；文本编辑器打开卡死 | 备选 |
| C. 仅设置 JSON | 导出 `project.json`，NBS 单独拖入 | 实现最简 | 不满足"包含 nbs 文件本身" | ❌ 不满足需求 |

**选 A**。理由：zip 写入器已在 `buildZip` 里实现且过测试；NBS 保持二进制原样（不受编码影响）；单文件即可完成"换机恢复"。

---

## 3. 工程文件格式（方案 A）

文件扩展名 `.nbsproj`（zip，STORE 不压缩——NBS 本身已压缩过，再 deflate 收益低且需额外实现）。

```
song.nbs              # 原始字节，逐位不变（导入时直接喂 parseNBS，不再重新序列化）
project.json          # 设置载荷，schema 同 localStorage payload（v: 2）
manifest.json         # 元信息：格式版本、导出时间、工具版本、校验
```

`project.json` = 现有 `saveStateNow()` 的 payload **原样**（同一 schema、同一 v 号），额外加：

```json
{
  "format": "nbs2schematic-project",
  "formatVersion": 1,
  "savedAt": 1759...,
  "toolVersion": "2026-10-15",
  "song": { "fileName": "canon in d major Loop.nbs", "bytes": 123456, "sha256": "…" }
}
```

`manifest.json` 只放 `formatVersion` + `song.sha256`，用于快速校验与未来兼容。

**为何 project.json 与 localStorage 同 schema**：导入时可直接复用 `loadSavedState` 的校验逻辑（[index.html:3435](../../index.html)），任何字段不合法 → 整体拒绝并报错，不产生半应用状态。

## 4. 功能设计

### 4.1 导出

**入口**：生成区工具栏，`<button id="projectExportBtn">⬇ 导出工程文件 (.nbsproj)</button>`（仅载歌后可见，与 `downloadBtn` 同门控）。

**行为**：
1. 若 `AppState.song` 为空 → 禁用（按钮 hidden）。
2. 导出前强制执行 `saveStateNow()`（确保内存态与载荷一致），然后取同一 payload 对象。
3. 用现有 `buildZip([...])` 打包三个条目。
4. 下载 `<歌名>.nbsproj`（`sanitizeFilename` 复用）。

**细节**：
- SHA-256：浏览器 `crypto.subtle.digest` 异步；若不可用（file:// 老浏览器）→ 省略字段，不阻塞导出。
- 不做压缩（STORE），保持 NBS 原字节；文件大小 ≈ NBS + 几 KB。

### 4.2 导入

**入口**：
- 拖到现有 dropzone（`#dropzone`）——扩展名为 `.nbsproj` 时走工程导入分支；
- 或 `#fileInput` 的 `accept` 增加 `.nbsproj`。

**行为**：
1. 读 ArrayBuffer → 解析 zip 目录（新增 `readZip()`，仅需 STORE 条目，无压缩方法 0 之外的支持）→ 取 `song.nbs` 与 `project.json`。
2. 校验：
   - `format === 'nbs2schematic-project'` 且 `formatVersion <= 1`；
   - `song.nbs` 存在且非空 → `parseNBS` 成功（失败 → 报「工程文件内的 NBS 已损坏」，不改动当前会话）；
   - `project.json` 过 `loadSavedState` 同一套校验；
   - 若 `song.sha256` 存在 → 校验（不符 → 警告但**允许继续**，因为可能是有意改动过的 NBS；提示「工程记录与本文件不一致」）。
3. 应用：`song.sourceFileName` 设为 `song.nbs 的原名`（来自 `project.song.fileName`）；`onSongLoaded(song, bytes)` 后**强制**用工程内的 `project.json` 应用（**优先于 localStorage**，避免同名同大小文件误命中旧存档）。
4. 失败时不改动当前会话（先全部校验后应用）。

### 4.3 与 localStorage 的关系

| 场景 | 行为 |
|---|---|
| 导入 `.nbsproj` | 用工程内配置**覆盖** localStorage 中该 key（并 `saveStateNow()` 落盘） |
| 直接拖 `.nbs` | 行为不变（优先 localStorage 恢复） |
| 导出 | 不改变 localStorage |

可选增强（**本期不做**）：导出时勾选「不含 NBS，仅设置」→ 生成 `.json`。留作后续。

## 6. 风险与边界

| 风险 | 处理 |
|---|---|
| 手写 zip 读取器出 bug（zip64 / 压缩方法其他） | 只支持 **STORE + 非 zip64**；其他情况明确报错「不支持的 zip 格式」；测试覆盖构造用例 |
| 载荷 schema 与 localStorage 漂移 | 抽 `buildStatePayload()` 单一来源 + 双向测试锁定 |
| 导入后与 localStorage 冲突 | 导入强制覆盖 + 立即落盘；测试断言 |
| `crypto.subtle` 在 file:// 不可用 | 降级省略 sha256，不阻塞 |
| 大文件内存 | NBS 上限已是 256MB（`NBS_MAX_FILE_BYTES`）；zip 读取整读，与现有行为一致；文档注明 |
| 安全（zip 炸弹） | 解压只读 STORE、条目名白名单（仅 `song.nbs` / `project.json` / `manifest.json`），拒绝其他条目与超大解压尺寸 |

## 7. 验收标准

1. **重新加载**（用户 2026-11-07 明确要求）：导出 → 刷新页面/换浏览器/清空数据 → 导入工程文件，恢复为**与导出时一致的会话状态**——
   - 音轨池勾选、参考标记（♪）、参考车道类型/起点/特效勾选与全部模板参数
   - 车道池分组、车道起点、音量还原勾选
   - 轨道 0 起点、歌词句子与全部歌词设置、目标版本、自定义乐器映射、soundIdMap、sfxPitchStep、矿车监听开关
   - 界面呈现（各 section 可见性、布局窗口位置、生成统计）与**重新生成产物逐字节一致**（同输入 → 同输出）
2. 导出的 `song.nbs` 与原始文件 **sha256 相同**。
3. 损坏/伪造的 `.nbsproj` → 明确报错且当前会话不变。
4. 三套件全绿，基线写入 README 与 memory。
5. 不回归：直接拖 `.nbs` 仍走 localStorage 恢复。

**测试锁定（关键）**：smoke 用例走「导出产物 zip → 解包 → 模拟刷新（清空 AppState）→ 导入 → 逐字段比对 + 生成产物 JSON 比对」，确保「重新加载」不是口头承诺而是断言。
