## 1. 问题与根因（均已代码定位）

### 问题 1：复制车道后，新车道显示勾选但无音量还原效果

**根因**：[index.html:3891](../../index.html) `duplicateLane`（函数头 3872）只复制 `tracks` 与 `start`：
```js
AppState.lanes.splice(li + 1, 0, { tracks: [...src.tracks], start: start || { dz: 0, dy: 1 } });
```
丢掉了 `volRestore`。渲染层 [index.html:4814](../../index.html) 读 `!!lane.volRestore`，若字段丢失应显示**未勾选**——用户看到「已勾选」，说明还有第二条路径（复制后手动勾选，或存档回填时序）。T1 断言须同时覆盖「字段复制」与「渲染勾选」两端，不要只改一行就收工。

**修复**：复制时带上 `volRestore`：
```js
{ tracks: [...src.tracks], start: start || { dz: 0, dy: 1 }, volRestore: !!src.volRestore }
```

### 问题 2 + 3：大音量位置错误（三个叠加根因，按实际影响排序）

**用户语义（三条合起来是自洽的）**：
- v=100 → 盒在该轨道原位 `zAnchor`（诉求 3）
- 同一车道的盒展开中，最响的那颗恒在靠近玩家的一侧（诉求 2：左侧车道大音量靠右、右侧车道大音量靠左）
- 物理上增益随距离衰减 → 更轻 = 更远；更响（v>100）= 更近

**根因 A：监听让位平移（**主因**，v1 规划完全漏掉）**

`volRestore` 强制要求矿车监听（[index.html:5876](../../index.html)），而监听启用时 [index.html:1689-1695](../../index.html) 有全局让位：
```js
const shift = Math.max(0, 2 - minZc);
for (const c of chains) if (!c.isRefLane) c.zc += shift;
```
- 用户把车道拖到 z=−24 → shift=26 → **实际锚点 +2**，v=100 的盒在 +2，不在用户放置的 −24。
- 更关键：**布局图预览用的是平移前的 `l.start.dz`**（[index.html:5901](../../index.html)），用户看到的车道位置和生成结果不是同一套坐标。
- 让位把「最低链」顶到 z=2 → **玩家（z=0 行走行）恒在所有车道左侧**——这就是用户说的「强制以左侧为玩家的位置」。

**根因 B：主链中位数重定位（次因）**

`solution volRestoreZLine` 把主链 `c.zc` 改写到全部目标 z 的中位数（[index.html:1731-1735](../../index.html)）。若该车道大部分音符 v<100，中位数 > 锚点 → **整条链向远离玩家方向漂移**，而 v=100 的盒仍在锚点 → 表现为「最大音量的音符盒跑到了链的左边」。这是 ±15 红石功率预算的必然代价：目标 z 跨度 >30 时链必须移动才能覆盖，属于设计取舍（见 §7.3）。

**根因 C：公式无符号（**休眠缺陷**）**

`volRestoreReqZ`（[index.html:1539](../../index.html)）恒返回正的绝对距离。但注意：**让位后所有真实链 zc ≥ 2，锚点恒为正 → 该缺陷当前不可能被触发**。一旦 §7.0 选 (b)/(c) 允许负侧车道，它立刻变成主因。所以本次必须修，但不要把它当成用户所见的解释。

**注**：v1 规划曾把网格边界列为受影响项——**误报**。主链重定位后分支相对 `c.zc` ±15，[index.html:1759-1761](../../index.html) 已用重定位后的 `c.zc ± 15`，`zOffset` 也用重定位后的 `zcList`；负侧由 `zExtra` 平移兜底。此两项无需改动。

## 2. 新增益模型（v2 修正）

### 2.1 现状 vs 目标（v2 修正方向）

| | 现状 | 目标 |
|---|---|---|
| 距离 | `hypot(z, yb+1)` | 不变（高度差参与，物理正确） |
| 100% 基准 | `g0 = gain(zAnchor)` | 不变 |
| v=100 | 返回 +zAnchor 的绝对值 → **负侧被镜像** | `zAnchor`（含符号，原位） |
| v<100 | `|z|` 更大（更远）——**方向本就正确** | 不变（更远 = 更轻） |
| v>100 | `|z|` 更小（更近）——**方向本就正确** | 不变（更近 = 更响） |
| 方向 | 恒正，**无符号** | 恒同侧：`sign(z) = sign(zAnchor)`，不跨 z=0 |
| 边界 | 恒 `≥1` | 正侧 `≥1`；负侧 `≤−1` |

> v1 规划此处曾把「v<100 更近」当目标——**错误**。物理上增益随距离衰减，v<100 只有更远才更轻；且用户「左侧轨道大音量靠右」即「小音量靠左（更远）」，与公式一致。

### 2.2 新公式（v2 修正上溢分支）

```js
// 玩家在原点 (0,0)；盒在 (z, yb+1) 的距离。不变。
function volRestoreGain(z, yb) {
  return Math.max(0, 1 - Math.hypot(z, yb + 1) / 48);
}

// 目标盒 z：保留 zAnchor 的符号；v=100 恰回 zAnchor；v<100 更远；v>100 更近（夹到同侧最近 1 格）
function volRestoreReqZ(v, zAnchor, yb) {
  const yv = yb + 1;
  const side = Math.sign(zAnchor) || 1;        // zAnchor=0 → 默认右侧（见 §7.1）
  const g0 = volRestoreGain(zAnchor, yb);
  const target = g0 * v / 100;                 // v=100 → g0 恰为锚点增益
  if (target >= 1) return side * 1;            // 目标超模型上限 → 同侧最近格（v1 曾误写 sqrt(48²−yv²)，那是增益 0 的最远点）
  const d = 48 * (1 - target);
  if (d <= yv) return side * 1;
  const z = Math.sqrt(d * d - yv * yv);
  return side * Math.max(1, z);
}
```

**数值自检**（zAnchor=−24，yb=0，g0≈0.4995）：

| v | target | d | 返回 |
|---|---|---|---|
| 100 | 0.4995 | 24.02 | **−24**（原位） |
| 50 | 0.2498 | 36.01 | −36（更远，增益 25%） |
| 120 | 0.5994 | 19.23 | −19（更近，增益 60%） |
| 200 | 0.999 | 0.048 | −1（夹到同侧最近格） |
| 0 | 0 | 48 | −48 → 调用方已过滤 v=0 |

### 2.2.1 关键性质：正侧零回归（本轮审视的核心产出）

`zAnchor > 0` 时 `side = +1`，新公式逐行退化为旧公式：
- `target >= 1` 分支：旧 `return 1`，新 `return +1` —— 同值；
- 主体：旧 `z < 1 ? 1 : z`，新 `+max(1, z)` —— 同值；
- `volRestoreZLine` 的末端 clamp `Math.max(zLine, 1)` —— 同值。

**结论：让位后的现有布局（锚点恒 ≥ 2）在新公式下产物逐字节不变**。现有 validate V1–V5 全部断言无需改期望值即应通过——这是最强的回归护栏：若实施后 V1–V5 有任何一条红，说明改错了。新增断言只需覆盖负侧（V1b/V1d/V6）与复制（T1/T2）。

**已实测**（v=1..127 × zAnchor=2..40 × yb=0..4 = 22320 个组合，逐个比对旧实现）：**差异计数 0**。

### 2.3 主链重定位 `volRestoreZLine`（v2 修正末行 clamp）

新模型下 `zs` 全同号（zAnchor≠0），排序/中位数/跨度/夹取策略**全部保留**，但末行必须按符号钳：
```js
// 现状 L1564：return Math.max(zLine, 1);   ← 强制正，负侧必炸
const limit = Math.sign(zAnchor) || 1;
return limit > 0 ? Math.max(zLine, 1) : Math.min(zLine, -1);
```

`c.zc = Math.round(c.volZLine)`（L1735）对负值同样成立（JS `Math.round(-11.5) = -11`，≤1 格偏差，增益误差 <1/48，可接受）。

**已实测**：现有 V1 三条用例（`zLine([100,90,80],2,0)=6.7387`、`([100,5,100],2,0)=17`、`([100,200],2,0)=2`）在新实现下逐值复现。

### 2.4 分支放置的预算约束（v2 新增——v1 漏掉，负侧会崩）

现状 [index.html:2147](../../index.html)：
```js
const dzEnd = Math.max(1 - zc, Math.min(15, Math.max(-15, dzRaw)));
```
`zc = −24` 时 `1 − zc = 25`，`Math.max(25, ...)` **强制 dzEnd=25**：越权 ±15 预算（红石功率 15 上限，末端盒不触发）+ 整条链结构被拉长。`step = dzEnd > 0 ? 1 : -1`（L2183）本身已支持负方向，放置循环（L2185-2196）也正确，**不需改**。

**正确写法**：分支不得落在 z=0、不得跨 0，且限 ±15：
```js
const zOffMin = zc > 0 ? 1 - zc : -15;   // 相对主链的偏移下界（正侧不越过 z=1；负侧无行走行约束，仅 −15）
const zOffMax = zc < 0 ? -1 - zc : 15;   // 相对主链的偏移上界（负侧不越过 z=−1）
const dzEnd = Math.max(zOffMin, Math.min(zOffMax, Math.max(-15, Math.min(15, dzRaw))));
```
- `zc=24`：`[−15, 15]`（`1−zc=−23` 不生效）
- `zc=−24`：`[−15, 15]`（`−1−zc=23` 不生效）
- `zc=1`：`[0, 15]`——v>100 无法更近，`dzEnd=0` 走主位分支（truncated 告警可保留语义：`dzEnd !== dzRaw`）
- `zc=−1`：`[−15, 0]`——对称

### 2.5 UI 提示失真（v2 新增）

[index.html:4815](../../index.html) `g0Hint = volRestoreGain(lane.start.dz, lane.start.dy)` 用的是**未让位的用户原值**，实际锚点 = `start.dz + shift`。新模型下语义改为「本轨原位为 100%」，百分比注明为近似（或去掉具体数值），避免用户按提示心算后对不上。

## 7. 待确认

### 7.0 【架构级，最优先】监听让位平移 vs 「原位」语义

`volRestore` 强制开监听 → 让位 `shift = max(0, 2 − minZc)`（[index.html:1691](../../index.html)）。**`minZc` 包含轨道 0**（默认 dz=0），所以默认布局的 shift 恒 = 2；用户把唯一一条链拖到 −24 时 shift = 26，锚点实际落在 +2。

| 2（数值） | v1 的 `target>=1 → side*sqrt(48²−yv²)` 反了——那是增益 0 的最远点，不是最近点。改 `side*1` |

| 4（让位） | **架构级**：监听让位 `shift=max(0,2−minZc)` 且 minZc 含轨道 0 → 默认 shift 恒 2，负起点被平移 → 用户「强制左侧视角」与「原位不成立」的真正来源 |
