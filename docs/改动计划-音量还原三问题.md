## 1. 用户报的 3 个问题 + 根因

### 问题 1：复制车道后显示勾选但无音量还原

`duplicateLane`（[index.html:3891](../../index.html)）只复制 `tracks` 与 `start`，丢 `volRestore`。

**但这不是唯一一处**——见 §2「新发现 N1」。

### 问题 2 + 3：大音量位置错误

**根因 A（主因）：监听让位平移**
`shift = Math.max(0, 2 − minZc)`（[index.html:1691](../../index.html)），`minZc` 含轨道 0（默认 dz=0）→ 默认 shift 恒 2；用户拖到 −24 时 shift=26。让位后所有链 zc ≥ 2，玩家（z=0 行走行）恒在同一侧 —— 这就是「强制以左侧为玩家」的直接来源。

**根因 B（次因）：主链中位数重定位**
`volRestoreZLine` 把主链改写到全部目标 z 的中位数。多数音符 v<100 时中位数远离锚点 → 整条链向远离玩家方向漂移（实测：速度分布 20~127 时漂移 +15 格），v=100 的盒仍在锚点 → 视觉上「最大音量的盒跑到了链的端头」。

**根因 C（休眠）：公式无符号**
`volRestoreReqZ` 恒返回正的绝对值。让位后锚点恒 ≥2 → 当前触发不到；但一旦 §3.1 改让位就立刻成为主因。

## 2. 20 轮审视新发现的 4 个缺陷

### N1【同类，严重】`assignUnassigned` / `applyPackBtn` 连 `start` 一起丢

[index.html:3925](../../index.html)：
```js
AppState.lanes = lanes.map(l => ({ tracks: l.tracks }));   // 丢 start + volRestore
```
[index.html:6228](../../index.html)：
```js
AppState.lanes = packed.map(tracks => ({ tracks }));       // 丢 start + volRestore
```
两者随后都调 `syncLaneStarts()`，把每条车道起点重置为 `i*3+3`、`dy=0`。

**用户可见后果**：点一次「＋ 自动并入未分配音轨」或「🧩 应用无冲突打包建议」，**所有车道的手动起点被静默清空，且声像还原勾选全部丢失**。这比问题 1 严重——它会毁掉整个布局。

[rindex.html:3578](../../index.html) `rebuildLanesAuto`（「自动分配」按钮）同样丢 start，但它是显式的「重建」，语义上可接受，仅需在按钮上写明「会重置全部起点」。

### N2【结构，最严重】主链重定位会覆盖其他车道，且无任何占用检测

`VoxelGrid.set`（[index.html:1511](../../index.html)）静默覆盖，无守卫。音量还原车道的主链重定位（`c.zc = Math.round(volZLine)`）后，在 [index.html:2115-2116](../../index.html) **无条件**写中继器与底座、[index.html:2150-2151](../../index.html) 无条件写主位粉+雪块、slot±1（[index.html:2262](../../index.html) 附近）也无条件写。

**只有分支路径做了占用检查**（[index.html:2186](../../index.html)）。实测：A 车道（v=70）漂到 zc=19，占据 [18,19,20]，B 非还原车道在 z=20 → **B 的音符盒被静默替换成 A 的红石粉**，产物结构损坏、B 丢音，无任何警告。

### N3【语义】主链重定位使 `geometry.volRestore` 与实际不符

`volRestoreEntries`（[index.html:1737](../../index.html)）记录 `anchorZc`（重定位**前**）与 `zLine`（重定位**后**），但下游只有 validate 用。**UI 布局图**（[index.html:5901](../../index.html)）仍按 `l.start.dz ± 15` 画，与产物实际位置（`round(volZLine)`）最多差 15+ 格。用户看到的布局图和生成的 litematic 是两套坐标。

### N4【一致性】`sfxBoundNoteLine` 的音量还原分支偏移 vs 参考车道粒子

音量还原分支末端盒在 `zc + dzEnd`（[index.html:2215](../../index.html) `sfxBoundNoteLine(t, pick.layerIdx, dzEnd)`），该函数用 `lane.zc + slotZ`（[index.html:1878](../../index.html)）算粒子 dz —— 逻辑正确。但 **`refMode` 下该函数直接 return**（[index.html:1865](../../index.html)），绑定行由虚拟参考车道段生成，那段用的是 `lane.zc − railChain.zc`（[index.html:1979](../../index.html)、[index.html:2440](../../index.html)），**不含 `dzEnd`**。即：开了 refMode + 音量还原 + 单线式参考车道时，粒子位置不跟随实际盒位。

## 3. 需要定夺的 4 项（含完整影响面）

### 3.1【架构，最优先】监听让位策略

**现状代码**（[index.html:1689-1695](../../index.html)）：
```js
const minZc = Math.min(...chains.filter(c => !c.isRefLane).map(c => c.zc));
const shift = Math.max(0, 2 - minZc);      // ← 全局，最左的那条决定所有链
for (const c of chains) if (!c.isRefLane) c.zc += shift;
```

**关键事实（本轮实测，纠正前几版文档的错误）**：

| 事实 | 说明 |
|---|---|
| `minZc` 恒含轨道 0 | 默认 `lane0.start={dz:0,dy:0}` → 默认 shift 恒 = 2 |
| **gen-example 不启用监听** | `grep -c listener testdata/gen-example.mjs` = **0** → 改让位**不动** gen-example 基线（旧文档说会动，错） |
| validate 只有 2 处启用监听 | L2/L3（只有轨道 0，无音轨车道）与 V2–V5（lane0 dz=0 + 车道 dz=6） |
| L2/L3 断言 | `minBoxZ ≥ zOffset+1`、行走行全空、`sz(启用) = sz(未启用)+2` |
| smoke M | lane0 dz=0 + 车道 dz=6，断言锚点 8 |

**四个方案的实际影响**：

| | (a) 现状 | (b) 取消平移+默认2+校验 | (c) 逐链静默 | **(d) 逐链+告警** |
|---|---|---|---|---|
| 代码量 | 0 | 大（含存档迁移） | 一行 | 一行 + 明细 |
| 默认布局产物 | 不变 | **等价**（lane0 默认 2，shift=0，zc 仍 2） | 不变（轨道0 shift=2） | 不变 |
| 用户拖到 −24 | 推到 +2 ✗ | 保持 −24 ✓ | 保持 −24 ✓ | 保持 −24 ✓ |
| 诉求「v=100 在 −24」 | ✗ | ✓ | ✓ | ✓ |
| 旧存档兼容 | — | **需迁移**（dz=0 会撞 0，一打开就报错） | 自动（dz=0 链自动 shift=2） | 自动 |
| 测试改动 | 0 | V2–V5 + smoke M **约 40 处期望值**（锚点 8→6） | 同 (b) | 同 (b) |
| 用户知情 | 否 | 报错 | 否（静默平移） | **是**（明细写「车道 N 起点 0→2」） |

**(b) 与 (d) 的真实差别**：默认布局下产物**完全相同**。(b) 把隐式平移换成显式默认值 2，代价是旧存档必须迁移；(d) 只改 `shift` 的作用域，旧存档自动兼容。

**推荐 (d)**：改动最小（一行 `Math.min(...all)` → 逐链 `c.zc`），旧存档零迁移，用户能看见平移，默认布局产物零变化。唯一成本是 V2–V5/smoke M 的期望值要改（因为车道 dz=6 不再被推到 8）——这是**期望值该改**，不是回归。

> 拒绝 (b) 的理由：存档迁移是新增的失败面，而它换来的产物与 (d) 完全相同。
> 拒绝 (a) 的理由：用户明确报了诉求 3，且布局图与产物坐标长期错位是真实 bug。

### 3.2 N2 的修法（碰撞覆盖）

**既有原则可直接引用**（[index.html:1889](../../index.html)、[index.html:2122](../../index.html) 两处）：
> **「声音缺失优于破坏结构」**

**修法**：重定位**前**检测，撞了就**放弃重定位**（保持 `c.zc` 原值），退回现有的「分支 ±15 截断 + 告警」模式。

```js
// 在 c.zc = Math.round(c.volZLine) 之前
const newZc = Math.round(c.volZLine);
const clash = chains.some(o => o !== c && !o.isRefLane
  && Math.abs(o.zc - newZc) <= 2);        // slot 区间 [zc-1, zc+1] 相交
if (clash) {
  c.volZLine = c.zc;                       // 放弃重定位
  stats.discardedDetails.push(`组 ${c.groupIndex+1}：音量还原重定位目标 z=${newZc} 与其他车道冲突，保持原点 z=${c.zc}（超出 ±15 的音将截断）`);
}
```

**为什么不选「夹取到安全区间」**：需要 30+ 行搜索逻辑与大量边界处理，收益只是少丢一点音量精度；而「放弃重定位」退回的模式**现有代码已完整实现**（含截断告警），零新增失败面。

**注意顺序**：N2 必须在 N5 之前做。先修 N5（clamp 1→2）会把「zc=1 部分重叠」变成「zc=2 完全重叠」，更糟。

### 3.3 N1 的修法（四处数据丢失）

四处语义不同，不能一刀切：

| 位置 | 行为 | 修法 |
|---|---|---|
| `duplicateLane`（[L3891](../../index.html)） | 插入一条，其余不动 | 加 `volRestore: !!src.volRestore`（`start` 已有） |
| `assignUnassigned`（[L3925](../../index.html)） | **只追加**，前 N 条顺序不变（`map` 保序） | 前 N 条按下标继承 `start`+`volRestore`；新增的给默认 `dz=i*3+3` |
| `applyPackBtn`（[L6228](../../index.html)） | **完全重排**，无法对应 | 二次确认文案明确「会重置全部起点与音量还原」；用户取消则零副作用 |
| `rebuildLanesAuto`（[L3578](../../index.html)） | 同上，且按钮本身就叫「自动分配」 | 已有语义，只需按钮 title 补一句「会重置全部起点」 |

**`assignUnassigned` 可按下标继承的证明**：


### 3.4 N4 的修法（refMode 粒子偏移）

**修**（不是标注限制）：`refMode` 的绑定行锚点（[index.html:1979](../../index.html)、[index.html:2440](../../index.html)）用 `lane.zc − railChain.zc`，但主位盒实际在 `lane.zc + slotZ`。音量还原分支时 `slotZ = dzEnd`，参考粒子的 dz 应同步。

实现：把每 tick 的 `slotZ` 记进一个 `Map<tick, slotZ>`，虚拟参考车道段读取它；未命中则用 0（旧行为）。

## 4. 公式改动（已实测）

### 4.1 `volRestoreReqZ`

```js
function volRestoreReqZ(v, zAnchor, yb) {
  const yv = yb + 1;
  const side = Math.sign(zAnchor) || 1;        // D1：0 → 右
  const g0 = volRestoreGain(zAnchor, yb);
  const target = g0 * v / 100;
  if (target >= 1) return side * 1;            // D2：上溢夹同侧 1 格
  const d = 48 * (1 - target);
  if (d <= yv) return side * 1;
  const z = Math.sqrt(d * d - yv * yv);
  return side * Math.max(1, z);
}
```

**已实测**：正侧（`zAnchor ≥ 2`）与旧实现 **22320 个组合零差异** → 现有 V1–V5 断言无需改。

### 4.2 `volRestoreZLine` 末行（v3 修正：下限 1 → 2）

```js
const limit = Math.sign(zAnchor) || 1;
return limit > 0 ? Math.max(zLine, 2) : Math.min(zLine, -2);
```

**为什么是 2 而不是 1（N5）**：链上第 3 音符盒在 `zc − 1`、第 2 在 `zc + 1`。
- 让位保证 `minZc_new = max(minZc, 2)` → 重定位前 `zc ≥ 2`，`slot2 = zc−1 ≥ 1` 安全。
- 但重定位**之后**若 `zc = 1`，`slot2 = 0` 正好是矿车行走行（`z=0` 恒空气的设计不变量被破坏）。
- **实测触发条件**：锚点 2 时中位 velocity ≥ 101.8；锚点 ≥10 时 ≥ 127（即 NBS 满音量）。**满音量是极常见情况**，不是边角。

负侧同理：`zc = −1` 时 `slot1 = zc + 1 = 0` 撞行走行 → clamp `≤ −2`。

### 4.3 分支预算（L2147）—— v1/v2 都漏掉

```js
// 现状：Math.max(1 - zc, Math.min(15, Math.max(-15, dzRaw)))
// zc = -24 时 1−zc = 25 → 强制 dzEnd=25，越权 ±15
const zOffMin = zc > 0 ? 1 - zc : -15;
const zOffMax = zc < 0 ? -1 - zc : 15;
const dzEnd = Math.max(zOffMin, Math.min(zOffMax, Math.max(-15, Math.min(15, dzRaw))));
```

### 第三轮核心结论

**N2（碰撞检测）是所有修复的前置条件**：
- 不改 N2 就修 N5 → 把 zc=1 的「部分重叠」变成 zc=2 的「完全重叠」，更糟；

### 实施期新发现（推翻了 v3 的两个结论）

**① D4 原推荐 (d)「逐链让位」是错的。** 逐链平移会破坏链间相对间距：默认布局下轨道 0 被推到 z=2、车道停在 z=3，车道的第 3 位盒（z=2）正好撞上轨道 0 的中继器——主链断裂。v3 里「(d) 产物与 (b) 等价」的判断只比较了轨道 0 自身，漏看了邻链。

改为 **方案 (f)**：
```js
const hitsWalkRow = realChains.some(c => Math.abs(c.zc) <= 1);   // 有链的盒列含 z=0
if (hitsWalkRow) {
  const shift = Math.max(0, 2 - Math.min(...realChains.map(c => c.zc)));
  for (const c of realChains) c.zc += shift;                      // 全局平移，保间距
}
```
- 无链撞行走行 → **零平移**（用户把车道拖到 −24 就保持 −24，诉求 3 成立）
- 有链撞行走行 → 退回旧的全局平移（与现状逐字节一致）
- **代价为零**：215 + 359 断言全部不改即通过，`gen-example` 产物解压后逐字节相同（仅 `TimeModified` 时间戳 4 字节差异）

**② N4「refMode 粒子偏移」是伪缺陷。** 参考车道的 `volRestore` 在 [index.html:1658](../../index.html) 被硬性设为 `false`（`isRef ? false : ...`），而音量还原的放置路径是 `if (c.volRestore && listenerActive)`——两个条件互斥，不可能同时成立。v3 里「三条件同时成立」的假设不成立，该项撤销。

**③ N6「托底破坏行走行」被 N5 覆盖。** `zc ≥ 2` 保证 `slot2 = zc−1 ≥ 1`，盒永远不会落到 z=0，托底也就不会在 z=0 下方补雪块。无需改代码，`N5a` 的断言已覆盖。
