# 修改方案：让位规则三维化 + g0 增益护栏（v2 最终版）

> 日期：2026-11-08 · 依据：用户实测 `debug.debug.json`（4325 音符 / 23 链 / 8 条音量还原车道）
> 状态：**待实施**（本文件即执行方案；调研过程见 v1 历史与本文件 §1）

---

## 0. 一句话

让位规则把「矿车在哪行走」误当成「车道在 Z 上压没压 0」——矿车实际只走**布局 y=0、z=0 的一条线**。判定改为三维后，用户布局（轨道 0 在 z=0 但 y=24）**零平移**，8 条音量还原车道全部回到拖放位置，`g0` 从 0 / 0.95 恢复为约 0.50。

## 1. 证据（debug.debug.json 实锤）

布局：`lane0Start = {dz:0, dy:24}`；22 条音轨车道 dz 在 ±2…±24、dy 0…22。

旧判定 `realChains.some(c => Math.abs(c.zc) <= 1)` **只看 Z**，命中轨道 0（dz=0，无视 dy=24）→ `minZc = −24` → `shift = 26` → 23 条链全部 +26：

| lane | 用户拖的 dz | 实际 anchorZc | g0 | 后果 |
|---|---|---|---|---|
| 1/3/5 | −24 | +2 | 0.95/0.91/0.94 | 左右翻转（−24 变成右侧 +2） |
| 2/4/6 | +24 | +50 | **0.000** | 音量还原完全失效 |
| 7 | 23 | +49 | **0.000** | 同上 |
| 8 | −23 | +3 | 0.84 | 左右翻转 |

连带 292 条「超 ±15 截断」明细全部来自 4 条 `g0 = 0` 的车道（目标增益恒 0 → 每个盒都被钳到边界）。

**关键事实：行走行是三维的 (x, 0, 0)，不是「z=0 的整面」。**

- `listener_start` 把矿车 summon 到**布局原点** (0,0,0)；`listener_follow` 每 tick `tp ^1 ^0 ^0` → 恒在 y=0、z=0，沿 x 推进（[index.html](../../index.html) `buildListenerFunctions`）。
- 一条链写进这条线的可能层：底座 `yb`、信号/盒 `yb+1`、轨道 0 导轨 `yb+2`、防掉落托底 `yb−1`、监听 CB `yb+3 / yb+4`。
- ⟹ **真正占用行走行 ⟺ `|zc| ≤ 1` 且 `yb ∈ [−4, 1]`**。

用户布局里轨道 0 的 yb=24：它的方块全在 y=24…28，行走线 y=0 上什么都没有 —— 这就是「把轨道 0 拖高仍触发全局平移」的根因。

## 2. 为什么否决上一轮讨论的「方案 B」（轨道 0 单独让位）

1. **前提不成立**：轨道 0 不需要让位。它承载链头 CB，不在行走线上；行走线在布局原点，与任何链的 `zc` 无关（CB 的 x/z 跟着轨道 0 走，矿车不跟）。
2. **无必要地改用户坐标**：方案 B 仍会把轨道 0 从 0 推到 +2，用户没要求、也无需要。
3. **与用户另一条车道列重叠**：g22 在 dz=2 → 轨道 0 推到 2 后盒列 [1,3] 与 g22 [1,3] 完全重合（不同 Y 不发生物理碰撞，但违反「无必要不动」原则，且给 N2 的 z-only 碰撞护栏制造假冲突）。

## 3. 新规则（改动点 1：让位判定）

[index.html:1698-1719](../../index.html) 判定式加 Y 条件，**保留全局平移机制**：

```js
const hitsWalkRow = realChains.some(c => Math.abs(c.zc) <= 1 && c.yb >= -4 && c.yb <= 1);
if (hitsWalkRow) {
  const minZc = Math.min(...realChains.map(c => c.zc));
  const shift = Math.max(0, 2 - minZc);
  if (shift > 0) {
    for (const c of realChains) { c.zc += shift; laneShifts.push({ groupIndex: c.groupIndex, shift }); }
  }
}
```

- 命中 → 全局平移 `shift = max(0, 2 − minZc)`（保持链间相对间距）
- 不命中 → `shift = 0`，**一个坐标都不动**
- 参考车道不参与（纯虚拟，现状保留）
- 明细文案不变（`矿车行走行让位：…`），日志逐链写出位移

### 3.1 全局平移必然解除占用（证明）

设命中链中最小 zc 为 `minZc`，`shift = max(0, 2 − minZc)`：
- 若 `minZc < 2`：`shift = 2 − minZc` → 平移后最小 `zc' = 2` → 全部链 `|zc'| ≥ 2` → 盒列不含 0。∎
- 若 `minZc ≥ 2`：已无链能命中（`|zc| ≥ 2 ⟹ !(|zc| ≤ 1)`），矛盾，不会进入此分支。

### 3.2 为什么不逐链平移

上轮已实证：逐链平移破坏链间间距（轨道 0 → 2、邻居停在 3 时，邻居第 3 位盒 z=2 撞轨道 0 中继器，主链断裂）。全局平移是既有、被测试覆盖的机制，只在「确有占用」时启动。

### 3.3 边界与残余保守性

- `yb ∈ [−4, 1]` 覆盖所有可能写进 y=0 的层；对无导轨/无 CB 的普通链在 `yb = −4..−2` 略保守，代价只是极端布局多平移一次（安全方向）。
- 确有链占用时，高处无关链也被整体 +shift —— 与现状行为一致；相对间距保持，不产生新重叠。
- volRestore 分支本来就永不写 z=0（`zOffMin/zOffMax` 双约束），无需额外条件。
- N2 重定位护栏仍只按 Z 列（`|Δzc| ≤ 2`）判定、不看 Y：不同高度的链列重叠会误拦。属既有「声音缺失优于破坏结构」的保守策略，本次不改（最小变更）。

## 4. g0 = 0 护栏（改动点 2）

[index.html:1739](../../index.html) 计算 `c.volG0` 之后：

```js
if (!(c.volG0 > 0)) throw new Error(
  `组 ${c.groupIndex + 1}：音量还原锚点 z=${c.zc}、yb=${c.yb} 距行走行 ≥ 48 格（增益为 0），`
  + '音量还原无法表达——请把该车道拖到 |z| ≤ 40 后重新生成');
```

- 触发条件：`hypot(zc, yb+1) ≥ 48` → 全部目标增益恒 0 → 每个盒都会被 ±15 截断堆在边界，音量还原**静默失效**（用户布局的 4 条车道即此，仅明细里写「重定位」看不出来）。
- 生成入口已有 try/catch → `showError(err.message)`（[index.html:6098](../../index.html)），无需改 UI。
- 只在该车道勾了音量还原时判；普通车道拖到荒远处不受影响。
