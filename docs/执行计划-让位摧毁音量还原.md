## 2. 为什么让位会平移 26 格

[index.html](../../index.html) 当前逻辑：

```js
const hitsWalkRow = realChains.some(c => Math.abs(c.zc) <= 1);   // 有链含 z=0 吗
if (hitsWalkRow) {
  const shift = Math.max(0, 2 - Math.min(...realChains.map(c => c.zc)));  // 全局平移
  for (const c of realChains) c.zc += shift;
}
```

**你的布局里轨道 0 在 z=0** → `hitsWalkRow = true` → `minZc = −24` → `shift = 26` → 全体 +26。

问题在于：**轨道 0 自己在 z=0 撞行走行，却要拉着所有其它车道一起平移 26 格**。

## 3. 三个可选方案

### 方案 A：只平移撞行走行的车道（其余不动）

```js
for (const c of realChains) {
  const s = Math.max(0, 2 - c.zc);   // 只有 zc < 2 的链被推
  if (s > 0) { c.zc += s; laneShifts.push(...); }
}
```

**问题**：会破坏链间距。轨道 0 推到 2、车道 1（−24）推到 2 —— 两条链重叠。

### 方案 B：轨道 0 独占让位，其余车道按「是否撞行走行」独立判定

```js
// 1) 只让轨道 0 保证不撞行走行（它承载矿车跟随 CB，位置是功能性的）
// 2) 其它车道：只在自己撞行走行时才平移
// 3) 平移后做碰撞检测，撞了就报错让用户挪
```

**问题**：你现在的布局里 −24/+24 两侧都不撞，理论上零平移 —— 但**轨道 0 在 z=0** 仍会被推到 2。
轨道 0 推 2 后与车道 1（−24）相隔 26 格，不冲突 ✓。这是**最小且正确**的方案。

### 方案 C：不做全局平移，改为在生成时校验 + 让用户在布局图里自己挪

```js
// 只检查：任何真实链的盒列含 z=0 → 报错中止，提示「车道 N 压在行走行上，请挪开」
```

**优点**：语义最干净，绝不静默改用户坐标。
**缺点**：默认布局（轨道 0 dz=0）一打开就报错，需要改 `lane0.start.dz` 默认值到 2。

---

## 4. 推荐：方案 B（轨道 0 独立让位 + 其它车道按需）

理由：
- 你的实测数据里，**23 条车道有 22 条本来就不撞行走行**，不该被推。
- 轨道 0 承载矿车跟随 CB，必须不撞行走行 → 单独推它是合理的。
- 你拖在 −24/+24 的车道保持原位，诉求 3 与诉求 2 同时成立。

### 具体实现

```js
const laneShifts = [];
if (listenerActive) {
  const realChains = chains.filter(c => !c.isRefLane);
  for (const c of realChains) {
    // 轨道 0 必须让位（矿车沿它的 zc 列行走）；其它车道只在自己压在行走行上时让
    const mustShift = c.isDefaultRail || Math.abs(c.zc) <= 1;
    if (!mustShift) continue;
    const s = Math.max(0, 2 - c.zc);
    if (s > 0) { c.zc += s; laneShifts.push({ groupIndex: c.groupIndex, shift: s, reason: c.isDefaultRail ? '轨道 0' : '压行走行' }); }
  }
  // 平移后碰撞检查：任何两条链的 [zc−1, zc+1] 相交 → 明细告警
}
```

### 需要同步处理的

1. **`hitsWalkRow` 的旧语义要保留一部分**：轨道 0 恒让位（否则矿车撞盒）。
2. **平移后碰撞检查**：方案 B 下若用户把两条车道都拖到 z=0，都会推到 2 → 重叠 → 必须报错。
3. **测试**：现有 `D4a/D4b/D4c/D4d` 四条全部要改期望值。

## 5. 另一个必须修的问题：`g0 = 0` 静默失效

即使不让位，**任何车道拖到 |z| ≥ 48 都会让 `g0 = 0`**，音量还原完全失效但只在明细里写「重定位」看不出问题。

**建议**：生成时检测 `c.volG0 <= 0` → 报错中止或强警告：

```js
if (c.volRestore && c.volG0 <= 0) {
  throw new Error(`车道 ${c.groupIndex + 1} 的音量还原锚点 z=${c.zc} 超出 48 格可听范围（增益为 0），请把车道拖近玩家`);
}
```

## 6. 757 个音符丢弃的构成（已查清）

从你的 `discardedDetails`（1059 条）分类统计：

| 类别 | 条数 | 说明 |
|---|---|---|
| **同刻多音** | **757** | 音量还原「每 tick ≤1 盒」策略：和弦只保留 velocity 最高者 |
| 超 ±15 截断 | 293 | **让位导致的二次伤害**（见下） |
| 重定位告知 | 7 | 碰撞护栏拦下的重定位 |
| velocity=0 | 1 | |
| 让位告知 | 1 | |

**结论**：757 全部是「同刻多音」——你那条车道每 tick 有多个音符，音量还原模式只保留最响的一个。
这是**设计行为**（每 tick 只能放 1 个盒），不是 bug。徽章此前只报「超 3 位」所以显示无冲突，
现在（`e5fee53`）已改为同时报两类。

**但那 293 条「超 ±15 截断」是让位造成的**：lane 2/4/6/7 被推到 z=50，`g0 = 0`，
目标增益恒 0 → 反解出的 |z| 恒 48 → 全部超出 ±15 → 全部截断。让位修复后这些会自然消失。
